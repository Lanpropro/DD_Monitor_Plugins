# 网络代理 v0.1

开发预览，插件 ID：`proxy_control`。通过插件管理内置代理内核，导入订阅和节点。当前仅 Windows x64 提供内核自动准备；其他平台可自行选择兼容的 Mihomo 程序。

## 使用方式

1. 点击左侧「网络代理」，在图标旁打开面板，默认进入「总览」。首次使用进入「配置」；需要准备内核时展开「内核设置」，开发机已准备好时可跳过下载。
2. 点击「添加配置」，填写服务商／配置名称，选择「订阅地址」「本地 Clash／Mihomo 配置」或「节点链接」，输入服务商提供的资料。
3. 点击输入框下方的「导入订阅并启动」（文件／节点链接显示对应的导入按钮）；订阅地址也可按回车确认。编辑已有订阅时显示「更新订阅并启用」。这一步同时下载、校验、载入节点并启动代理，成功后保存这份配置；输入期间不会自动请求订阅。
4. 导入中显示进度并锁定输入，完成后显示节点数量、自动进入「代理」。失败时保留输入，可修改后重试，原有已保存配置不被失败的导入覆盖。节点由官方内核解析，支持 YAML／JSON `proxies`、Base64 订阅和内核支持的节点 URI。点击节点卡片切换，并重新播放直播间；卡片上的勾选只在内核确认切换成功后更新。
5. 「总览」可启动／停止服务、选择已保存的服务商配置并点击「使用配置」、快捷切换节点和调整启动时恢复代理。停止状态使用配置只载入节点，运行时切换配置会重启内核；配置页选择卡片只进入编辑，点击导入才更新并启用。总览启动使用当前已保存配置，不提交编辑中的草稿。
6. 在总览点击「停止」结束内核，恢复软件原本使用的系统／环境代理；配置和节点选择保留。

不是用户的节点或订阅就不能凭空建立可用线路。内置内核只是代理客户端的一部分，不提供代理服务本身。

## 安装与入口

本地候选包：`dist/proxy_control-0.1.zip`；尚无公开下载插件附件、Release 或标签。在宿主设置 → 插件中导入并重启，日常统一从宿主根目录 `run.cmd` 启动。清单最低版本为 0.7.2，当前开发版实际需具备左侧功能轨接口、现有代理读取链路及 `ddm.ui` 导出的 `SegmentedControl`、`ToggleSwitch`、`SelectControl` 共享组件；不能仅凭版本号认为旧安装包已含这些组件。

从功能中心固定「网络代理」到关注栏左侧。点击图标在旁边展开主窗口内的面板，最大约 660 × 480 个逻辑像素，小窗口内自动限制尺寸和位置；面板暂时覆盖局部内容，不改变直播墙布局边距或尺寸，不创建独立设置窗口。再次点击图标、右上角收起按钮、点击面板外或在面板内按 Esc 收起。收起保留当前页和未确认的输入，不结束代理；卸载或退出宿主会停止插件自有内核并恢复原环境。

入口停止时为空心盾牌箭头，运行时改为实心盾牌勾选，面板内徽标同步。未运行且收起时为灰色，面板打开时为主题蓝色，代理运行且收起时为绿色；打开且运行时显示蓝色图标及绿色状态点。使用宿主支持的可选 QAction 同步导航选中、功能中心和关闭状态，图标不再被入口的静态染色覆盖。仅临时测试节点时不会显示代理运行状态。面板外轮廓使用宿主连续圆角路径，并裁剪原生子控件及内部背景。

面板参照代理客户端的左侧导航分成「总览」「代理」「配置」「连接」四页，使用宿主字体和深浅色主题令牌。总览展示服务状态、当前配置、当前节点和内核 RSS；代理页包含名称、协议、选中勾选和延迟状态，支持搜索。节点卡片在宽面板中显示两列，窄面板中显示一列，仅内部滚动并绘制可见项，不为每个节点创建一组 QWidget。配置页管理命名的多份服务商配置，内核路径和准备按钮继续折叠。没有添加虚拟网卡、系统代理开关、流量曲线或未测量的数据。

「连接」显示通过本插件核心的活动连接：目标／协议、代理链、命中规则和上下行累计流量，悬停可查看完整文本；不包含其他应用或绕过核心的请求。仅本页可见且代理运行时每 2 秒读取本机鉴权接口，切页／收起／停止立即取消请求；快照上限 512 KiB、显示前 100 条，超限暂停，可手动刷新。下方保留最多 64 条本次会话的操作与固定分类错误，不保存到配置，不展示核心原始日志或请求 URL／凭证。失败的连接可能已经从活动列表消失，应结合最近错误判断；不能将一条错误归因到所有连接。

视觉布局参考 FlClash：左侧图标与文字导航、选中胶囊、独立页面标题、轻描边圆角卡片和开关；配色沿用宿主主题。总览将服务与快捷设置、配置与节点分别并排，小窗口改为单列。配置页默认展示服务商卡片，点击卡片或「添加配置」在同一面板内进入表单，「配置列表」返回；导入按钮就近显示，内核设置折叠。图标与勾选使用矢量绘制，避免依赖特殊字体字符。

订阅地址和配置路径使用单行输入，节点链接保留多行输入；订阅地址只清理首尾空白，中间的空格或换行会给出明确提示，不擅自拼接多条链接。配置页显示就近的导入确认按钮；总览「启动代理／重新载入」用于载入当前已保存资料，空资料只引导前往配置，不提交后台请求。编辑后会清除旧错误并提示修改尚未确认。

「测延迟」在代理停止时也可点击：临时加载一个内核执行测试，全程不应用软件代理环境，完成或取消后释放；代理已运行时复用当前内核。只在用户点击时测试当前搜索结果，经官方内核代理集合接口请求页面上选择的检测地址。默认与当前 FlClash 一致，使用 Google `https://www.gstatic.com/generate_204`、单节点最多等待 8 秒；也可选择 YouTube 204。每次最多 2 个请求，界面显示准备状态、逐节点结果和完成／成功／超时／失败计数；再次点击或收起面板取消队列及在途请求，已完成结果保留，迟到结果不更新新会话。

内核 HTTP 503 显示为「检测失败（503）」，401／404 等显示相应接口错误，不直接推断节点永久不可用。停止状态整批均失败时，再通过当前预选节点执行一次最多 10 秒的连接诊断，仍不修改软件代理环境；临时内核只在这一步内部使用代理模式，用户保存的模式不变。诊断完成或取消后回收内核。诊断只能说明预选节点的这次结果，不代表全部节点或其他目标网站。

内核警告输出仅在内存中提取 DNS、TLS、鉴权、连接拒绝、不可达、超时等固定分类后丢弃，未完整写入宿主日志；日志记录分类、阶段、数量、测试目标代号和 HTTP／传输错误码，不记录节点名、订阅 URL、令牌或密码。结果表示这个测试地址的连接延迟，不等于直播播放延迟或带宽。检测默认值参考 [FlClash 常量定义](https://github.com/chen08209/FlClash/blob/main/lib/common/constant.dart)，API 503 的行为参考 [Mihomo 检测接口源码](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/hub/route/proxies.go)。

已核对 [FlClash 实际测速实现](https://github.com/chen08209/FlClash/blob/main/core/delay.go)：查找节点后调用 Mihomo `URLTest`，带超时和并发限制，区分超时／失败；本插件通过内核健康检查 API 调用同一测试机制，保留最多 2 并发。FlClash Go 层回退超时与 UI 传入值有区别，不能把回退常量等同于所有用户的实际参数。

2026-11-09 用户真实复测中预选节点出现 DNS 解析失败。核心现使用内部 DNS 与专用节点域名解析，直接向 `223.5.5.5`、`119.29.29.29` 查询，256 条 LRU 缓存；不监听 DNS 端口、不修改系统 DNS、不启用 fake IP／TUN。首次 DoH 方案在用户当前网络仍失败，公共域名诊断确认普通 DNS 可达而两个 DoH 地址超时，故移除该依赖；真实核心已能通过当前默认配置解析公共检测域名。混合代理端口确认可连接且节点确认后才接管软件网络。修复后仍需用户真实线路复测，本机 DNS 夹具与公共域名诊断不代表海外服务可达。

启动后新建连接使用内置代理，正在播放的直播间需要重新播放。插件不会自动中断直播或录制。成功启动且「启动软件时恢复代理」开启时，重启会恢复内置代理；关闭此项或点击「停止」后，下次启动软件不会自动接管网络。首次安装默认停用。切换服务商仍只运行一个内核，每份配置记住各自确认后的节点。

停止后保留节点名称和协议，可在「代理」页预选，下次启动使用该节点。旧配置没有节点缓存时，更新后的首次启动会自动补读一次；也可以在节点页点击「载入节点」。补读只临时启动核心解析配置，不修改本软件的代理环境，完成后释放内核，并保持未启动状态。完全没有配置时，启动按钮引导填写并拒绝后台启动，不修改网络设置。

节点旁按名称、常见地区缩写或原有旗帜标识显示本地 SVG 旗帜；台湾、台北、TW、Taiwan 和原有台湾旗帜标识统一使用中华人民共和国国旗。显示时去掉原有旗帜 Emoji，避免重复或不一致；交给核心的节点标识完整保留。未识别地区显示通用图标，不声称通过 IP 验证实际服务器位置。包含 23 份 SVG、合计约 22 KiB，按需绘制并共享图标缓存，不为节点创建额外控件或查询地理位置服务。

名称优先保留手动命名；未命名时读取订阅的 `profile-title`（含 Base64 编码）或下载文件名。服务商未提供名称时显示订阅域名，本地文件使用文件名，不从 URL 的令牌或路径猜测供应商品牌。旧版「我的配置」会迁移为域名，并在补读订阅成功后更新为服务商提供的标题。

## 出站模式与作用范围

总览的快捷设置复用设置组件库的分段选择器，直接展示「规则／全局／直连」三个选项及当前模式说明；恢复开关和下拉选择也复用同一组件库。模式保存到本机，运行时通过 Mihomo API 确认后生效，无需重启内核；已有连接仍需重新播放。三种模式都只控制接入本插件的本软件请求，不修改 Windows 系统代理或开启 TUN，也不会让从桌面单独打开的其他软件自动使用插件。

| 模式 | 行为 |
| --- | --- |
| 规则（默认） | 内置 B站／虎牙／斗鱼／抖音及相关 CDN 域名、私网地址直连，其余经所选节点 |
| 全局 | 接入核心的请求全部经所选节点；GLOBAL 组明确指向插件节点组 |
| 直连 | 接入核心的请求直接连接目标，不经过代理节点 |

规则模式使用 `configuration.py` 内的有限域名清单，不加载 GeoIP／GeoSite 数据库，不代表覆盖所有中国网站、IP 形式的 CDN 或服务商原始规则。用户原有 FlClash 的系统代理／TUN 若开启，仍可独立影响其他应用，与本插件模式是两套设置。模式含义与接口参考 [Mihomo 运行模式](https://wiki.metacubex.one/config/general/#运行模式) 和 [控制 API](https://wiki.metacubex.one/api/)。

旧版配置自动迁移：原来的内置订阅、节点与内核路径保留；已移除的手动外部代理地址会清理，旧系统／直连／外部模式迁移为停用内置代理。原有宿主的系统代理能力继续由宿主提供。

首次准备核心使用官方固定版本 `v1.19.33` Windows amd64 compatible 包，按 GitHub 公布的 SHA256 校验。下载和解压异步进行，停止状态不加载内核。也可从插件目录使用：

```powershell
python prepare_core.py --directory C:/DDM-runtime/proxy-control
```

然后选择输出的 `mihomo.exe`。没有在插件安装包中捆绑内核，更新或准备内核不会更改 Windows 系统代理。

## 接入范围与限制

插件设置本软件进程中的标准 HTTP／HTTPS／ALL_PROXY／NO_PROXY 环境变量。宿主的 Requests、urllib、Streamlink、HLS 转发、海外弹幕代理解析、mpv 与新启动的 FFmpeg 均沿用现有代理能力；没有全局替换网络库函数。回环地址始终直连，插件内核的子进程不继承这些代理，避免连接回自己。

它不是 TUN／VPN，不接管操作系统流量，也不能强制改写不读取这些设置、显式禁用代理的第三方插件，或独立浏览器登录页面的网络行为。已建立的连接不会热切换。原有系统代理／环境代理不属于插件管理的进程，不会被插件结束。

导入配置时只使用节点内容，用户配置中的 TUN、LAN 监听、系统 DNS、控制 API 和路由规则不直接套用。插件自行生成回环监听、随机控制口和临时鉴权 Key。默认不启用健康检查轮询、GEO 数据库或系统服务；延迟测试只在用户触发时执行。首版由用户手动选节点，不自动挑选最快节点；未知格式会显示加载失败，不发送给在线订阅转换网站。

订阅最多 4 MiB，内核下载最多 48 MiB，网络读取缓冲 64 KiB，下载最多等待 60 秒。内核最多等待 30 秒载入节点。临时会话文件在停止后清理；程序、订阅缓存和个人设置保留在数据目录 `utils/proxy_control/`，其中 `profiles.json` 保存命名配置、`preferences.json` 保存当前配置和启动选项，不要纳入 Git 或分享。

订阅 URL、节点配置可能含密码或令牌，按用户输入保存在上述本机数据目录，**没有承诺加密存储**。安装包、日志和错误提示不写入这些内容；不要把本机数据目录作为插件包发送给别人。

## 内存与验证

启动后运行一个自有内核，每两秒显示该进程 RSS，停止后释放；这个数字不包含宿主 Qt／网络缓冲增量。尚未证明内置方案比已有客户端更省内存、更快或更稳定。

使用带 PySide6 的宿主解释器：

```powershell
python tests/check_proxy_control.py --host ../DD_Monitor_CE --core C:/DDM-runtime/proxy-control/mihomo.exe
python tests/check_contributing.py
python tests/check_packages.py --host ../DD_Monitor_CE
python -m compileall -q plugins/proxy_control tests/check_proxy_control.py
git diff --check
```

专项测试使用临时目录和本机服务，不读取真实账号、不发送真实弹幕。覆盖面板开关／定位／窗口尺寸适配、直播墙布局不变、三页主题渲染、草稿保留、节点卡片列数、命名配置迁移与切换、自动连接开关、搜索和选中状态、延迟测试鉴权／并发／取消，以及内核 HTTP 入口、Requests／urllib／HLS 转发、原生 mpv 与 FFmpeg、订阅下载、Base64 文件、真实 Shadowsocks 本机加密节点、节点切换、控制口鉴权、官方内核下载校验与停止回收。没有 `--core` 时实际内核检查会跳过；不能把跳过记为通过。

真实验收请使用用户自己的订阅和节点，从根 `run.cmd` 打开 YouTube／Twitch，核对播放、弹幕、切节点与停止后的表现，再采集 30 分钟稳定阶段内存与延迟。本机协议测试不代替真实线路、各类节点参数或高峰期稳定性验收。

## 模块职责与参考项目

| 模块 | 职责 |
| --- | --- |
| `plugin.py` | 宿主左侧入口及卸载协调 |

| `panel.py` | 四页导航、总览／代理／配置、草稿与宿主主题；不拥有内核 |
| `connection_page.py` | 连接详情及会话事件展示，随可见性启停监测 |
| `connections.py` | 本机连接 API、快照解析、有界缓冲及按需刷新；固定错误分类文字 |
| `visuals.py` | 图标、导航绘制、服务商卡片；开关与选择直接复用宿主公共组件 |
| `entry_icon.py` | 主入口的面板选中／代理运行形状、颜色与状态点 |
| `regions.py` | 名称地区识别、旗帜缓存和显示名；保留原始核心标识 |
| `node_list.py` | 节点数据模型与可见行绘制、搜索、选中及延迟展示 |
| `latency.py` | 手动延迟测试队列、最多两个请求、鉴权、取消与迟到结果过滤 |
| `controller.py` | 会话状态所有者、应用／恢复设置、准备流程和资源统计 |
| `environment.py` | 进程内代理覆盖及精确恢复，不操作注册表 |
| `configuration.py` | 用户输入、个人配置、隔离核心配置生成 |
| `profiles.py` | 命名服务商配置的本机存储及旧单份配置迁移 |
| `metadata.py` | 解析服务商标题／文件名与不含令牌的名称回退 |
| `network.py` | 有界异步下载；取消后忽略迟到回调 |
