# 网络代理 v1.0

开发预览，插件 ID：`proxy_control`。通过插件管理内置代理内核，导入订阅和节点。当前仅 Windows x64 提供内核自动准备；其他平台可自行选择兼容的 Mihomo 程序。v1.0 发布候选已准备；当前公开宿主 v0.7.2-hotfix.2 缺少必需公共控件，无法加载本候选，按维护者要求暂缓发布，等待配套宿主兼容验证及发布确认。

## 使用方式

1. 首次启用插件会在内核缺失时自动下载、校验并安装，已有内核直接复用；准备失败时可展开「配置 → 内核设置」重试。点击左侧「网络代理」，在图标旁打开面板，默认进入「总览」。
2. 点击「添加配置」，填写服务商／配置名称，选择「订阅地址」「本地 Clash／Mihomo 配置」或「节点链接」，输入服务商提供的资料。
3. 点击输入框下方的「导入订阅并启动」（文件／节点链接显示对应的导入按钮）；订阅地址也可按回车确认。编辑已有订阅时显示「更新订阅并启用」。这一步同时下载、校验、载入节点并启动代理，成功后保存这份配置；输入期间不会自动请求订阅。
4. 导入中显示进度并锁定输入，完成后显示节点数量、自动进入「代理」。失败时保留输入，可修改后重试，原有已保存配置不被失败的导入覆盖。节点由官方内核解析，支持 YAML／JSON `proxies`、Base64 订阅和内核支持的节点 URI。点击节点卡片切换，并重新播放直播间；卡片上的勾选只在内核确认切换成功后更新。
5. 「总览」可启动／停止服务、选择已保存的服务商配置并点击「使用配置」、快捷切换节点和调整启动时恢复代理。停止状态使用配置只载入节点，运行时切换配置会重启内核；配置页选择卡片只进入编辑，点击导入才更新并启用。总览启动使用当前已保存配置，不提交编辑中的草稿。
6. 在总览点击「暂停代理」结束内核，恢复软件原本使用的系统／环境代理；配置和节点选择保留。

不是用户的节点或订阅就不能凭空建立可用线路。内置内核只是代理客户端的一部分，不提供代理服务本身。

## 安装与入口

本地候选包：`dist/proxy_control-1.0.zip`；尚无公开下载插件附件、Release 或标签。在宿主设置 → 插件中导入并重启，日常统一从宿主根目录 `run.cmd` 启动。清单最低版本为 0.7.2，当前开发版实际需具备左侧功能轨接口、现有代理读取链路及 `ddm.ui` 导出的 `SegmentedControl`、`ToggleSwitch`、`SelectControl` 共享组件；不能仅凭版本号认为旧安装包已含这些组件。

从功能中心固定「网络代理」到关注栏左侧。点击图标在旁边展开主窗口内的面板，最大约 660 × 480 个逻辑像素，小窗口内自动限制尺寸和位置；面板暂时覆盖局部内容，不改变直播墙布局边距或尺寸，不创建独立设置窗口。再次点击图标、右上角收起按钮、点击面板外或在面板内按 Esc 收起。收起保留当前页和未确认的输入，不结束代理；卸载或退出宿主会停止插件自有内核并恢复原环境。

入口始终使用地球与双向连接箭头的线框图标，按设备像素比生成，避免运行时实心地球在小尺寸下糊成一团。侧栏前景沿用宿主选中、悬停和主题色；运行时通过公共按钮属性 `workspaceRunning` 请求宿主在最终着色之后绘制右上角绿色圆点，面板收起时保留，停止后移除。该圆点需要包含宿主 d254e923 的配套源码。使用宿主支持的可选 QAction 同步导航选中、功能中心和关闭状态；仅临时测试节点时不会显示代理运行状态。面板外轮廓使用宿主连续圆角路径，并裁剪原生子控件及内部背景。

面板参照代理客户端的左侧导航分成「总览」「代理」「配置」「连接」四页，使用宿主字体和深浅色主题令牌。总览展示服务状态、当前配置、当前节点和内核 RSS；代理页包含名称、协议、选中勾选和延迟状态，支持搜索。节点卡片在宽面板中显示两列，窄面板中显示一列，仅内部滚动并绘制可见项，不为每个节点创建一组 QWidget。配置页管理命名的多份服务商配置，内核路径和准备按钮继续折叠。没有添加虚拟网卡、系统代理开关、流量曲线或未测量的数据。

「连接」显示通过本插件核心的活动连接：目标／协议、代理链、命中规则和上下行累计流量，悬停可查看完整文本；不包含其他应用或绕过核心的请求。仅本页可见且代理运行时每 2 秒读取本机鉴权接口，切页／收起／停止立即取消请求；快照上限 512 KiB、显示前 100 条，超限暂停，可手动刷新。下方保留最多 64 条本次会话的操作与固定分类错误，不保存到配置，不展示核心原始日志或请求 URL／凭证。失败的连接可能已经从活动列表消失，应结合最近错误判断；不能将一条错误归因到所有连接。

视觉布局参考 FlClash：左侧图标与文字导航、选中胶囊、独立页面标题、轻描边圆角卡片和开关；配色沿用宿主主题。总览将服务与快捷设置、配置与节点分别并排，小窗口改为单列。配置页默认展示服务商卡片，点击卡片或「添加配置」在同一面板内进入表单，「配置列表」返回；导入按钮就近显示，内核设置折叠。图标与勾选使用矢量绘制，避免依赖特殊字体字符。

订阅地址和配置路径使用单行输入，节点链接保留多行输入；订阅地址只清理首尾空白，中间的空格或换行会给出明确提示，不擅自拼接多条链接。配置页显示就近的导入确认按钮；总览「启动代理／重新载入」用于载入当前已保存资料，空资料只引导前往配置，不提交后台请求。编辑后会清除旧错误并提示修改尚未确认。

「测延迟」在代理停止时也可点击：临时加载一个内核执行测试，全程不应用软件代理环境，完成或取消后释放；代理已运行时复用当前内核。首次打开菜单自动测试一次（没有节点时等待本次展开期间载入）；也可手动测试当前搜索结果，经官方内核代理集合接口请求页面上选择的检测地址。默认使用 Google `https://www.gstatic.com/generate_204`、单节点最多等待 8 秒；也可选择 YouTube 204 或 Cloudflare HTTP（`http://cp.cloudflare.com/generate_204`）。每次最多 50 个在途请求，其余显示排队；卡片用一个共享时钟绘制转圈，隐藏停止刷新，界面显示准备状态、逐节点结果和完成／成功／超时／失败计数；再次点击或收起面板取消队列及在途请求，已完成结果保留，迟到结果不更新新会话。切换检测地址清除旧数值与汇总，保留当前节点选择，避免把不同目标的结果混在一起。

与 FlClash 比较时需确认当前分组的检测地址。以实际核对的 0.8.94 为例，[分组测试](https://github.com/chen08209/FlClash/blob/v0.8.94/lib/views/proxies/common.dart) 与 [地址选择](https://github.com/chen08209/FlClash/blob/v0.8.94/lib/providers/state.dart) 会优先采用分组 URL，再回退应用默认值；因此即使没有手动修改设置，也可能并非测试 Google。插件使用用户在节点页明确选择的地址，不自动导入订阅的分组与路由。HTTP 与 HTTPS、不同目标站点的数值不可直接比较；Cloudflare HTTP 供匹配使用相同地址的客户端，不保证更低延迟或所有线路兼容。

内核 HTTP 503 显示为「检测失败（503）」，401／404 等显示相应接口错误，不直接推断节点永久不可用。停止状态整批均失败时，再通过当前预选节点执行一次最多 10 秒的连接诊断，仍不修改软件代理环境；临时内核只在这一步内部使用代理模式，用户保存的模式不变。诊断完成或取消后回收内核。诊断只能说明预选节点的这次结果，不代表全部节点或其他目标网站。

内核警告输出仅在内存中提取 DNS、TLS、鉴权、连接拒绝、不可达、超时等固定分类后丢弃，未完整写入宿主日志；日志记录分类、阶段、数量、测试目标代号和 HTTP／传输错误码，不记录节点名、订阅 URL、令牌或密码。结果表示这个测试地址的连接延迟，不等于直播播放延迟或带宽。检测默认值参考 [FlClash 常量定义](https://github.com/chen08209/FlClash/blob/main/lib/common/constant.dart)，API 503 的行为参考 [Mihomo 检测接口源码](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/hub/route/proxies.go)。

预选节点 DNS 诊断继续区分域名不存在、没有可用地址、超时、请求被拒绝、上游错误、IPv6 禁用及 IP 版本不匹配，详细原因显示在连接页最近事件中；无法区分时明确显示未知，不记录私有域名。公共 DNS 查询成功并不等于节点域名及线路可用，当前真实用户节点的失败仍在排查。

完整 YAML／JSON 配置会保留 `hosts` 及 DNS 的主解析、节点解析、解析策略、地址族和 hosts 开关；订阅指定主 DNS 但未另设节点 DNS 时，节点跟随该解析器。不会用固定公共 DNS 覆盖供应商的这些配置。入站端口、控制口、TUN、完整路由、DNS 监听、fake IP 和缓存大小继续由插件隔离配置管理。仅记录导入的字段／映射数量，不输出私有值。配置兼容参考 [FlClash 构建配置逻辑](https://github.com/chen08209/FlClash/blob/main/lib/common/task.dart)。

每份配置独立保存「订阅格式」的 User-Agent：默认 `clash.meta/1.19.33 DDM-Proxy/1.0`，可选 Clash Verge（`clash-verge`）、FlClash（`FlClash`），或直接输入自定义标识；切换服务商时恢复各自选择，新配置始终使用通用默认值。订阅格式只影响该份配置的下载，不更改其他服务商或直播请求。版本更新保留已有配置明确保存的下载标识；缺少该字段时使用当前默认值。

本次用户提供的 XFLTD 教程要求 `clash-verge` 或 URL 中的 `flag=clash-verge`，应只为这份配置选 Clash Verge。插件不写死供应商域名，不自动改写用户链接中的令牌或查询参数。日志仅记录文档格式、节点数量及服务器地址类型计数，不记录地址、User-Agent 自定义值或凭证。请求格式修正本身不能证明真实线路错误已经解决。

YAML 解析私有携带 PyYAML 6.0.3 的 16 个纯 Python 文件（源文件约 209 KiB，MIT），无 C 扩展或额外服务；只在 YAML 会话载入时加载，文档提取后释放，尚未测量其真实宿主 RSS 增量。JSON 用标准库，URI／Base64 交由核心处理。来源与固定摘要见 `vendor/README.md`，不修改宿主依赖。错误的 DNS／hosts 会结束待加载会话并恢复网络，避免订阅异步回调中的异常让界面一直显示准备中。

已核对 [FlClash 实际测速实现](https://github.com/chen08209/FlClash/blob/main/core/delay.go)：查找节点后调用 Mihomo `URLTest`，带超时和并发限制，区分超时／失败；本插件通过内核健康检查 API 调用同一测试机制，采用 v0.8.94 的 [core/common.go](https://github.com/chen08209/FlClash/blob/v0.8.94/core/common.go) 中 50 项并发上限。FlClash Go 层回退超时与 UI 传入值有区别，不能把回退常量等同于所有用户的实际参数。

内核显式开启 `unified-delay` 和 `tcp-concurrent`，与 [FlClash 默认配置](https://github.com/chen08209/FlClash/blob/main/lib/models/clash_config.dart) 对齐。统一延迟先预热，再用第二次响应计时；第二次请求失败时，内核回退首次计时，两次请求共用单节点 8 秒期限，参见 [Mihomo URLTest](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/adapter/adapter.go)。这是测试地址的响应耗时，不能据此推算直播播放延迟；不同网络时刻、缓存和内核版本下仍可能与其他客户端不同。

混合入口启动前由 UDP 动态分配器选端口，再检查同号 TCP，冲突时分散探测非特权端口（总共最多 32 次），确保 TCP 与 UDP 在同一回环端口均可绑定，避免只检查 TCP 而选到 UDP 已占用或受系统限制的端口；控制 API 只需要 TCP。此检查不修改系统端口保留或防火墙，端口释放到内核绑定之间仍存在竞争窗口。

默认不强制覆写 DNS、不开启 IPv6；未提供 DNS 的配置使用系统解析，有明确配置则保留其解析器及地址族声明，完整配置的 `ipv6: true` 仍可启用 IPv6 节点。关闭 DNS 覆写不等于忽略供应商提供的 DNS。启用内部解析时缓存上限为 256；不监听 DNS 端口、不修改系统 DNS、不启用 fake IP／TUN。此前尝试固定公共 DNS／DoH 及强制开启 IPv6，均未解决真实故障，已按服务商截图要求取消强制覆写；证据与边界见增量记录。混合代理端口确认可连接且节点确认后才接管软件网络。修复后仍需用户真实线路复测，本机 DNS／hosts 夹具不代表海外服务可达。

启动后新建连接使用内置代理，正在播放的直播间需要重新播放。插件不会自动中断直播或录制。成功启动且「启动软件时自动连接」开启时，重启会恢复内置代理；关闭此项或点击「暂停代理」后，下次启动软件不会自动接管网络。首次安装默认停用。切换服务商仍只运行一个内核，每份配置记住各自确认后的节点。

停止后保留节点名称和协议，可在「代理」页预选，下次启动使用该节点。旧配置没有节点缓存时，更新后的首次启动会自动补读一次；也可以在节点页点击「载入节点」。补读只临时启动核心解析配置，不修改本软件的代理环境，完成后释放内核，并保持未启动状态。完全没有配置时，启动按钮引导填写并拒绝后台启动，不修改网络设置。

节点旁按名称、常见地区缩写或原有旗帜标识显示本地 SVG 旗帜；台湾、台北、TW、Taiwan 和原有台湾旗帜标识统一使用中华人民共和国国旗。显示时去掉原有旗帜 Emoji，避免重复或不一致；交给核心的节点标识完整保留。未识别地区显示通用图标，不声称通过 IP 验证实际服务器位置。包含 23 份 SVG、合计约 22 KiB，按需绘制并共享图标缓存，不为节点创建额外控件或查询地理位置服务。

名称优先保留手动命名；未命名时读取订阅的 `profile-title`（含 Base64 编码）或下载文件名。服务商未提供名称时显示订阅域名，本地文件使用文件名，不从 URL 的令牌或路径猜测供应商品牌。旧版「我的配置」会迁移为域名，并在补读订阅成功后更新为服务商提供的标题。

## 出站模式与作用范围

总览的快捷设置复用设置组件库的分段选择器，直接展示「规则／全局／直连」三个选项及当前模式说明；恢复开关和下拉选择也复用同一组件库。面板的普通操作、标题、提示、卡片表面及内核折叠分别使用公共 `ActionButton`、`TitleLabel`、`HintLabel`、`SettingsSurface` 和 `DisclosureButton`；输入框继承宿主主题，支持自定义 UA 的可编辑组合框保留原生编辑能力。节点及配置列表继续虚拟绘制，复用公共连续圆角路径和字号，不为每项创建控件。红色暂停电源、同宽展开列表与紧凑总览布局保留。

模式保存到本机，运行时通过 Mihomo API 确认后生效，无需重启内核；已有连接仍需重新播放。三种模式都只控制接入本插件的本软件请求，不修改 Windows 系统代理或开启 TUN，也不会让从桌面单独打开的其他软件自动使用插件。

| 模式 | 行为 |
| --- | --- |
| 规则（默认） | 内置 B站／虎牙／斗鱼／抖音及相关 CDN 域名、私网地址直连，其余经所选节点 |
| 全局 | 接入核心的请求全部经所选节点；GLOBAL 组明确指向插件节点组 |
| 直连 | 接入核心的请求直接连接目标，不经过代理节点 |

规则模式使用 `configuration.py` 内的有限域名清单，不加载 GeoIP／GeoSite 数据库，不代表覆盖所有中国网站、IP 形式的 CDN 或服务商原始规则。用户原有 FlClash 的系统代理／TUN 若开启，仍可独立影响其他应用，与本插件模式是两套设置。模式含义与接口参考 [Mihomo 运行模式](https://wiki.metacubex.one/config/general/#运行模式) 和 [控制 API](https://wiki.metacubex.one/api/)。

旧版配置自动迁移：原来的内置订阅、节点与内核路径保留；已移除的手动外部代理地址会清理，旧系统／直连／外部模式迁移为停用内置代理。原有宿主的系统代理能力继续由宿主提供。

首次启用插件时，若配置的内核不存在，会自动下载官方固定版本 `v1.19.33` Windows amd64 compatible 包，按固定 SHA256 校验后安装到数据目录 `utils/proxy_control/runtime/mihomo.exe`，并保存路径。需要联网，插件 ZIP 本身不捆绑内核；已有内核不重复下载。失败时会显示原因，可在“内核设置”点击“准备内核”重试。下载异步进行，校验和解压使用插件内工作线程，不依赖系统 Python；停止或卸载时协作取消并清理本次解压的临时文件。首次安装默认只准备内核，不开启代理或修改软件网络；原有自动恢复会等待内核准备成功后再执行。也可从插件目录使用：

```powershell
python prepare_core.py --directory C:/DDM-runtime/proxy-control
```

然后选择输出的 `mihomo.exe`。没有在插件安装包中捆绑内核，更新或准备内核不会更改 Windows 系统代理。

## 接入范围与限制

插件设置本软件进程中的标准 HTTP／HTTPS／ALL_PROXY／NO_PROXY 环境变量。宿主的 Requests、urllib、Streamlink、HLS 转发、海外弹幕代理解析、mpv 与新启动的 FFmpeg 均沿用现有代理能力；没有全局替换网络库函数。回环地址始终直连，插件内核的子进程不继承这些代理，避免连接回自己。

它不是 TUN／VPN，不接管操作系统流量，也不能强制改写不读取这些设置、显式禁用代理的第三方插件，或独立浏览器登录页面的网络行为。已建立的连接不会热切换。原有系统代理／环境代理不属于插件管理的进程，不会被插件结束。

导入配置时只使用节点内容，用户配置中的 TUN、LAN 监听、系统 DNS、控制 API 和路由规则不直接套用。插件自行生成回环监听、随机控制口和临时鉴权 Key。默认不启用健康检查轮询、GEO 数据库或系统服务；延迟测试在首次展开菜单或用户点击时执行。首版由用户手动选节点，不自动挑选最快节点；未知格式会显示加载失败，不发送给在线订阅转换网站。

订阅最多 4 MiB，内核下载最多 48 MiB，网络读取缓冲 64 KiB，下载最多等待 60 秒。内核最多等待 30 秒载入节点。临时会话文件在停止后清理；程序、订阅缓存和个人设置保留在数据目录 `utils/proxy_control/`，其中 `profiles.json` 保存命名配置、`preferences.json` 保存当前配置和启动选项，不要纳入 Git 或分享。

订阅 URL、节点配置可能含密码或令牌，按用户输入保存在上述本机数据目录，**没有承诺加密存储**。安装包、日志和错误提示不写入这些内容；不要把本机数据目录作为插件包发送给别人。

## 内存与验证

启动后运行一个自有内核，每两秒显示该进程 RSS，停止后释放；这个数字不包含宿主 Qt／网络缓冲增量。尚未证明内置方案比已有客户端更省内存、更快或更稳定。

使用带 PySide6 的宿主解释器：

```powershell
python tests/check_proxy_control.py --host ../DD_Monitor_CE --core C:/DDM-runtime/proxy-control/mihomo.exe
python tests/check_contributing.py
python tests/check_packages.py --host ../DD_Monitor_CE
python -m compileall -q plugins/proxy_control tests/check_proxy_control.py
git diff --check
```

专项测试使用临时目录和本机服务，不读取真实账号、不发送真实弹幕。覆盖面板开关／定位／窗口尺寸适配、直播墙布局不变、四页主题渲染、草稿保留、节点卡片列数、命名配置迁移与切换、自动连接开关、搜索和选中状态、延迟测试鉴权／并发／取消，以及内核 HTTP 入口、Requests／urllib／HLS 转发、原生 mpv 与 FFmpeg、订阅下载、Base64 文件、真实 Shadowsocks 本机加密节点、节点切换、控制口鉴权、官方内核下载校验与停止回收。没有 `--core` 时实际内核检查会跳过；不能把跳过记为通过。

真实验收请使用用户自己的订阅和节点，从根 `run.cmd` 打开 YouTube／Twitch，核对播放、弹幕、切节点与停止后的表现，再采集 30 分钟稳定阶段内存与延迟。本机协议测试不代替真实线路、各类节点参数或高峰期稳定性验收。

优先使用现有实现：[Mihomo](https://github.com/MetaCubeX/mihomo) 提供内核、节点解析与转换；[官方代理集合文档](https://wiki.metacubex.one/en/config/proxy-providers/)、[控制 API](https://wiki.metacubex.one/api/) 和 [端口文档](https://wiki.metacubex.one/en/config/inbound/port/) 提供配置依据。[Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev) 用于参考界面与内核分离的产品方式；没有复制其完整客户端或源码。

Mihomo 为 GPL-3.0，固定版本来源为 [v1.19.33](https://github.com/MetaCubeX/mihomo/releases/tag/v1.19.33)；内核独立下载和运行，其源码和许可归上游。原创插件代码沿用仓库 LICENSE。Qt、Requests、mpv、FFmpeg 等沿用宿主依赖和各自许可。

旗帜使用 [flag-icons](https://github.com/lipis/flag-icons) 的原始 4:3 SVG 子集，固定源码版本与 MIT 许可证随 `flags/README.md`、`flags/LICENSE.txt` 提供；未包含 `tw.svg`。

测速结果由控制器按配置身份及检测目标保存在应用会话内；启停、收起或节点列表刷新后恢复，不跨软件重启保存。再次测试清除此配置/目标的旧结果；配置或目标不同不混用。HTTP 请求每份响应缓冲 2 KiB，最多九个按需 Qt 网络管理器，测试结束/取消释放额外管理器，无常驻后台检测。

配置卡显示服务商在订阅响应 `subscription-userinfo` 提供的剩余流量及到期日期；统计随成功更新订阅刷新，并非实时用量查询。缺失、零上限或无效字段明确说明，超额不显示负百分比；没有统计时不绘制虚假的流量条。旧配置继续可读，UA/节点选择不变。

总览用电源图标按钮控制开启／暂停；开启时为蓝色操作，代理运行后为红色暂停操作，准备时同一位置显示取消图标。悬停提示和无障碍名称随操作更新。暂停会释放核心并恢复原网络环境，新的播放请求按当前环境重新连接。配置选择器填满卡片宽度，节点下拉沿用节点页的业务记录，显示旗帜、协议与本次延迟。

面板保持 660×480 上限和墙内原生子窗口；点击入口、外点或 Esc 收起。材质沿用宿主静态模糊与清晰控件的思路，只在展开前抓取所覆盖区域一次并缩到最多 330×240 做模糊，收起立即释放，不循环抓屏或改变播放布局。系统关闭透明效果、高对比或取样不可用时使用实色。该材质不是顶层 DWM Acrylic；背景在展开期间静止，调整窗口大小时回退实色，重新展开重新取样。

「启动软件时自动连接」仅恢复退出前仍保持开启的代理，手动暂停后不会在下次启动恢复。总览节点选择与上方模式控件铺满相同列宽；配置编辑沿用同款卡片，名称、导入方式、地址与兼容格式同宽同高。从其他菜单切回「配置」，或再次点击／激活当前「配置」菜单，返回配置列表；列表中再选配置才进入编辑。首次没有配置时保留导入引导。

FlClash 下载兼容预设采用已核对的 0.8.94 默认标识 `FlClash/v0.8.94 clash-verge Platform/windows`（[上游 package.dart](https://github.com/chen08209/FlClash/blob/v0.8.94/lib/common/package.dart)）；它包含服务商可能依赖的 `clash-verge` 兼容字段。不会替换已有配置手动保存的 UA，重新选择预设后在确认导入时生效。节点名称中的 `[V]` 等后缀按服务商原文保留；本地真实 Mihomo 回归确认 VLESS 能载入，本插件没有按协议过滤 VLESS。不同订阅标识、更新时间或服务商响应仍可能返回不同集合，比较时需使用同一有效订阅和客户端格式。

总览节点弹出列表使用与收起控件相同的逻辑宽度，随面板宽度调整；节点长名称和协议说明在实际行宽内省略，不再强制 280 px。代理服务的状态和电源在同一行；宽窗口两列独立紧凑排列，当前配置及资源占用紧跟服务卡片，节点卡片紧跟快捷设置；窄窗口仍按原导航内容顺序单列排列。
