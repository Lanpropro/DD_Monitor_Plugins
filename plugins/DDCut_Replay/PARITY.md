# ShadowReplay 完整功能对齐计划

状态：2026-11-05，用户提出的目标方向是先完整对齐参考功能，再集中讨论定制修改。本文固定目标与验收标准，不表示尚未实现的功能已经完成；当前实现状态仍见[功能对照](FEATURES.md)。

## 对齐基线与保留约束

- 以用户展示的2.25.1及已核对源码 `e340951fa500d3977f5b9981329a1939650da82f` 为固定基线，避免开发中追随上游变化而失去验收依据。
- 对齐功能、数据关系和操作闭环；界面继续优先复用DD监控室CE的组件、配色、字体和主窗口入口，账号、关注、导入和原录制入口保留。
- 参考项目是Rust/Tauri/Svelte，本项目是Python/Qt。逐模块评估复用后端、移植算法或接入依赖，不把复制页面当成功能实现，也不为复刻页面重建已有账号和直播平台功能。
- 参考快照附MIT许可证；实际引入第三方代码时保留原许可、版权与来源，记录具体版本和依赖。当前研究快照只是选读资料，不是已可构建的完整源码包；当前环境也未发现Rust/Cargo工具链。
- 复用原PR43，宿主新增接口仍进入配套PR161；每个可验收功能分别提交并更新记录，不逐次增加版本号。人工通过前不合并或公开发布，不中断用户当前录制。

## 实施批次与完成标准

各批按依赖推进，不把某一批完成描述为“全部复刻完成”。除专门的部署与外部接口验收外，功能必须通过根目录 `run.cmd` 在软件内复测。

| 批次 | 必须覆盖 | 自动验证与人工验收标准 |
| --- | --- | --- |
| 1. 多选区与素材生成 | 多个区间的增删改/启用、持久化、全部添加亮点、分别导出与顺序拼接；素材保存对应弹幕 | 多区间与单区间互不覆盖；重开恢复；输出逐个可解码、顺序与时长正确；进行中录制继续，取消不留下伪成品 |
| 2. 完整弹幕链路 | 普通弹幕/SC/表情记录、回放列表/搜索、播放同步与时间偏移、JSON/ASS导出、预览样式及视频压制 | 暂停/倍速/定位后弹幕时间正确；裁剪拼接后重新映射；无数据明确空态；实际平台延迟与高密度表现人工核查 |
| 3. 素材与剪辑工程 | 录播→素材→工程分层；多段排序/裁剪/分割、吸附、撤销/重做、波形、倍速；文字/贴纸/画中画/音频轨道 | 素材文件与工程分开保存；工程重开可编辑；预览与导出内容、声音、顺序和叠加位置一致；删除与取消均有可核查的行为 |
| 4. 字幕与高级导出 | 手动字幕与打轴、SRT、样式/压制、Whisper等识别与缓存；H.264/H.265、速度/画质/码率、完整录播合成与自动整场素材 | 字幕随片段裁剪/移动；识别缓存复用；编码选项真实生效，输出可解码；模型缺失、服务未配置和任务失败不伪装成完成 |
| 5. 投稿与封面制作 | 素材/工程/文件投稿、草稿/状态/重试、双比例封面、画面取帧、文字/贴纸编辑 | 离线接口替身验证参数和状态；账号隔离；真实上传/发布由用户明确触发和验收，不以替身测试冒充线上成功 |
| 6. AI、自动化与其他输入 | AI助手查询/分析、兼容模型配置、MCP、Webhook、RTMP接收、深链和Web/headless部署 | 接口有明确生命周期、状态与失败信息；使用本地测试端点/本地推流验证；真实外部服务与远程访问条件单独记录 |
| 7. 管理与完整回归 | 总览、磁盘/缓存统计、房间状态/录播日历、批量管理、任务历史及完整流程回归 | 统计来自实际文件/任务；本体入口与账号流程保持可用；真实直播录制→回看找亮点→素材→工程→字幕/封面→投稿草稿完成端到端验收 |

## 外部依赖怎样计入完成度

- 公开源码内的本地功能逐项对齐；模型需要真实安装和加载，不能只放按钮。
- 云端字幕、AI模型和平台投稿属于外部服务。实现兼容客户端、配置、状态和失败处理；实际使用取决于用户配置的服务和账号，不将他人的云服务端本身算成已复刻。
- 如果某项因依赖、接口或平台限制暂时不可用，保留在未完成清单中说明原因，不擅自删掉该功能，也不把界面占位标为完成。
- 每批交付报告源码提交、原PR、验证范围、剩余项和具体手测步骤。未经过人工真实运行的部分继续标为待验收。

## 完整对齐后的定制阶段

逐项核对[功能对照](FEATURES.md)的缺口后，按用户验收记录修改布局、默认参数、工作流和功能取舍。保留原参考行为与本体集成的回归用例，使定制改动能够比较和回滚。
