# DDCut Replay 首版设计

状态：2026-11-04 开发方案；流程和范围为本任务的实施选择，尚未经过用户人工验收。

当前范围调整（2026-11-05）：用户暂不考虑AI、自动化和内置素材库，素材管理准备交由其他软件；剪辑工程保留，直接引用外部视频文件。字幕先做手动编辑、SRT与压制，AI识别暂缓；现有录像库、录制行为与本地弹幕热度保留。当前对齐与验收范围以[对齐计划](PARITY.md)为准，下方早期范围描述保留历史。

## 当前增量：外部文件剪辑工程（2026-11-05）

参考固定快照的ProjectEditor/ProjectTimeline/ItemInspector与material-project架构，接入工程列表和同页编辑器，布局为左文件/中预览/右属性/下多轨。工程用独立JSON保存外部引用、主轨片段与附加内容，未建立素材数据库；自动保存、相对路径另存、缺失文件重新定位和会话内100步撤销重做。主轨磁吸编排，附加内容锚定来源片段时间，裁剪起点后隐藏，分割时复制跨界内容；同类重叠自动分轨。

主轨可裁剪/排序/分割/复制、0.25～4倍速与音量；附加图文、图片贴纸、视频画中画、独立音频支持位置/尺寸/透明度或入点/速度/音量/淡入淡出。主轨之外的附加尾部用黑屏静音补齐。音频波形从选中文件实际解码提取，最多2048个峰值，活动HLS按冻结的可读时长截取。

合成先复用已验证的精确选区（含HLS封口范围、可选主轨弹幕），再统一画布、帧率、音频格式并拼接、混音；图文复用本体中文字体。图文和画中画按统一视觉轨层级交错，连续图文组以透明帧管道生成临时FFV1无损片段，保留预乘alpha，再按顺序与视频合成；临时文件随任务清理。图片/文字围绕矩形中心旋转，视频使用相同中心与扩展透明边界，避免旋转裁角。旧JSON缺少visual_order时，读取后将原视频轨排列在原图文轨下方，保留旧画面。

画面手势通过Qt事件及MPV自身的鼠标/按键绑定进入GUI线程，避免原生视频子窗口吞掉操作；边框以MPV位图绘制，不创建浮窗。命中测试使用扣除黑边后的内容区域和逆旋转矩阵，四角缩放固定对角并保持比例；临时草稿只更新边框，释放一次提交到历史，Esc取消。预览使用同一合成器按当前位置生成8秒缓存，播放跨段等待，取消旧预览后更新，不伪称即时实时或实时内容拖动。退出先清理选择框、停止原生播放器和供帧任务，测试在正常Qt事件循环内完成窗口释放；初期发现的临时QImage生命周期错误已修复，并纳入原生导出验证。

## 当前增量：弹幕压制（2026-11-05）

选区页新增默认关闭的压制开关，开启强制精确H.264/AAC MP4，沿用已保存字号、透明度和偏移；预览开关独立。普通文字/本地图像表情/SC使用共享ChatScene与本体CommentRaster、SC配色/文本组件、内置思源弹幕字体。预览输出MPV位图，导出在任务工作线程逐帧绘制透明QImage，经有界管道输入FFmpeg overlay，避免完整帧序列落盘；显式使用预乘alpha以匹配Qt。实现依据：[FFmpeg overlay文档](https://ffmpeg.org/ffmpeg-filters.html#overlay)。

导出以原录像时间求值，保留裁剪开头正在移动的弹幕；多选区各自压制后再拼接。探测源显示尺寸、旋转、像素宽高比与帧率，变帧率按探测帧率输出。取消/失败先回收FFmpeg，再等待供帧线程退出，沿用临时文件和成品提交语义。JSON侧车仍独立保存，压制成品用对象包装 `video_burned/events`，兼容旧数组；成品列表与重新导入读取标记，默认关闭额外画面弹幕并禁止再次压制，避免重复叠加。缺失本地表情仅回退文字，不在导出时建立网络请求。

## 当前增量：多选区与完整弹幕回放（2026-11-05）

片段检查器现在分“选区/弹幕/标记”。选区以数组保存起止、启用状态和当前索引，兼容旧单选区；新增、删除、排序、全选及全部添加候选互不覆盖。时间轴显示全部区间，选中后复用入出点拖动。底部固定生成按钮及启用数量/总时长，选区页可滚动。分别导出逐个保留完成文件，顺序拼接先精确生成各段，再组成一个MP4；取消清理未完成临时输出。

新归档保存普通弹幕、SC及删除、表情和颜色字段，复用本体缓存/图片下载组件保存表情；不新建弹幕连接，不存观众ID或凭证。增量日志统一映射为媒体时间事件，普通弹幕供热度统计；列表用Qt虚拟模型检索，绘制直接用MPV bitmap overlay并复用本体文字/表情和SC配色组件。以真实time-pos驱动，无独立窗口；暂停、倍速、定位及大小变化不重载播放器。SC有效时间含删除事件；高密度画面限制轨道/速率，完整数据仍保留在列表和JSON。

每份录像保存画面开关、字号、透明度和时间偏移；偏移同时作用于画面、列表、热度及侧车。精确导出裁剪/拼接时间，JSON相对引用独立图片副本；视频重新导入时自动关联同名侧车。ASS为文字回退，尚不压入视频。快速复制受关键帧前滚影响，需弹幕同步时默认采用精确导出。本批仍不自建素材库、工程编辑器或自动化。

## 当前UI基线：先参考ShadowReplay（2026-11-05）

用户要求UI也先参考，再集中修改。插件继续原生Qt内嵌；本体外层入口不变。首批回看工作区采用大预览/底部播放与时间轴/右侧片段检查器：打开录像收起列表和筛选条，“录像列表”回到同页浏览；默认展开检查器，收起只扩展预览，不重载视频。选区输入、预览选区与亮点推荐放在同一检查器页，标记另页，生成按钮和当前选区摘要固定底部；导出设置在可滚动检查器内。时间轴分开热度、刻度与选区轨道，播放头贯穿，支持原定位/拖动/缩放。

深色工作区参照参考源码的舞台/面板底色和较小圆角控件，浅色仍随本体切换，视频舞台保持深色。本批未引入AI/自动化/素材库，也未放置尚无实现的弹幕、多选区或工程页面；未来页面继续按约定功能范围对齐。下方“优先本体视觉”和并排录像列表属于此前方案，当前以本段为准。

## 当前原生页面分类（2026-11-04）

- 顶层仅“录像库”和“回看与切片”。录像库内筛选正在录制、历史录播、已生成切片，共用搜索、刷新和打开操作；当前活动归档不混入历史，同会话已经轮转的旧归档仍可查看。
- 回看页为来源标题、预览与播放控制、真实媒体时间轴及右侧选区/标记工具。时间轴呈现可读范围、真实分段边界、播放头、入出点及标记，支持拖动、缩放和范围滚动，不用虚构波形代表媒体内容。
- 后台任务是两个页面共用的右侧面板，关闭不取消。面板参与布局避免遮挡原生 libmpv；窄窗口暂时收起选区工具，关面板恢复。导出结果写入切片分类，关闭时刚完成和旧持久成功任务也能恢复。
- 原画面墙录制按钮继续作为录制入口；有活跃录制进入回看，尚无素材时进入录像库。设置沿用本体设置入口。本次不修改 HLS 后端或版本号。

## 目标与范围

从画面墙录制或缓存进入专用工作区，找到录像、独立回看、设置单个时间选区、后台导出并找到成品。保留本体录制、原始流直存、快速保存、画质锁定和退出收尾。

本轮不实现多轨工程、自动热度分析、AI、字幕或投稿。不迁移已有录像，不改写播放后端。

## 模块及宿主边界

源码路径保留 `plugins/DDCut_Replay/`，运行时 ID 选为 `ddcut_replay`。清单 ID 管理 ZIP 顶层与安装目录；构建器以源码目录查 Git 跟踪文件，将内容映射至清单 ID，不改用户指定目录。

| 归属 | 职责 |
| --- | --- |
| 本体 RecordingManager | 原录制与缓存、FFmpeg 录制进程、快速保存与收尾；新增分段租约供插件使用 |
| 本体 PluginContext.recording | 只读来源/状态快照、通过 CaptureControl 发起操作、获取/释放可读分段；停用后拒绝新操作 |
| 插件 media.TaskHub | 扫描本体成品与显式导入、选区/标记持久化、记录来源和时间范围 |
| 插件 media/tasks | 工作线程探测、构建回看副本、FFmpeg 导出与进度、取消和原子提交成品 |
| 插件 workspace | Qt 工作区、预览、选区和任务反馈，不直接读写主窗口私有字段 |
| 插件 plugin | 全局入口、格子菜单、工作区和任务生命周期 |

录制生命周期：CaptureControl 校验设置/画质 → RecordingManager 获取独立流 → 10 秒分段 → 排除未封口尾段 → 正常停止/轮转后合并 → 保留回放或清理。插件通过桥接获取一次快照并占用对应分段；后台生成稳定回看文件后释放占用。用户刷新时取得新快照，不假装时间轴实时连续，也不将断流后的空白补成真实录像。

首版按回看副本内部连续媒体时间选区，原始房间/快照时间单独保留；不宣称断流段可映射为无缝墙钟时间。不同编码来源不强行拼成一条会话，失败时给出分段/编码提示。

## 导出与退出语义

- 快速复制保持原编码，选区可能按关键帧扩展；不能标为逐帧准确。精确剪辑用 H.264/AAC 重编码，耗时和画质变化明确显示。
- 耗时探测、合并、编码在工作线程；GUI 只提交操作和轮询已缓存状态。FFmpeg 无控制台、后台优先级。
- 输出写入任务专属临时文件，成功并确认可读才原子移动至新成品；取消/失败只清自己的临时文件，不覆盖旧成品。
- 预览默认静音。关闭窗口停止播放器；导出继续。插件卸载/退出取消插件任务并回收子进程，再释放分段租约；本体原录制按既有流程收尾。
- 预览副本和任务状态使用插件数据目录；标记只保存元数据，不移动原录像。任务日志不保存直播 URL、凭据或 Cookie。

4. 人工确认真实直播、长时间运行、听感与 DPI 后记录验收；不自动发布。

## 最新录制集成修正（0.1.3）

用户明确要求插件接管本体录制，工作区只负责回看、增长时间轴与快速切片；TS 是可选实现，不是固定格式要求。本条替代上方录制中心独立控制及每次生成回看副本的方案。

宿主增加带归属的会话工厂注册，默认会话不变；插件提供 `ReplayRecordingSession`。原按钮 → 原 CaptureControl → 原 RecordingManager → 插件会话，保留原画、取流/断线重连、轮转、空间检查、快速保存和退出收尾。卸载仅恢复新会话的默认工厂，不中断已开始的录制。

插件将可读分段直接写入独立录播目录，以 FFmpeg CSV 的已封口清单发布原生 MPV EDL 及录播元数据。分段目标 2 秒，复制编码时仍按源关键帧切割。每次打开/定位新增范围或读至末尾时更新预览索引，保留暂停与静音状态；不为每次增长强制重载正在看的旧位置。导出冻结提交时的分段列表，在工作线程生成 FFmpeg concat 输入，不复制整份录像。

容器沿用本体设置及兼容规则；支持 TS、普通 MP4 和 MKV 独立分段。每个普通 MP4 在关闭后进入时间轴，因此无需强制 H.264 或改造流为 fMP4。时间轴按媒体时间计时，断流空白不补帧，轮转/换编码建立新录播。底层复用 FFmpeg 分段与 libmpv 原生 EDL，不另起浏览器或流媒体服务。

现成方案依据：[FFmpeg 分段/HLS](https://www.ffmpeg.org/ffmpeg-formats.html#segment_002c-stream_005fsegment_002c-ssegment)、[MPV EDL 格式](https://github.com/mpv-player/mpv/blob/master/DOCS/edl-mpv.rst)。不复制第三方项目代码。


## 最新实现选择：沿用 ShadowReplay 的 HLS 归档思路

本条替代上一节新录播使用 EDL/CSV 的适配方案。用户要求优先采用参考项目的大体设计，并明确同一开发候选只追加原 PR/验收，不逐次增加版本号；当前0.1.3不变，commit区分验收包。

核对固定参考源码 e340951fa500d3977f5b9981329a1939650da82f：FLV经原生 record_to_hls 生成分段和清单；HLS输入保存源分段并保留fMP4初始化信息；活动归档使用EVENT、结束为VOD，recorder_manager通过本地读取层提供分段，时间轴和选区以录播档案为中心。这些是源码结论，没有运行或代替对方项目性能验收。

我们的适配沿用同一数据链路，复用宿主FFmpeg CLI处理各平台解析后的输入，使用标准HLS muxer写TS或fMP4。保留原编码和目录/画质/停止逻辑，内部归档容器由HLS后端管理。初始化段随切片、快速保存和租约保留，断线后的播放列表包含discontinuity；原生播放器从仅监听127.0.0.1的内部HTTP读取清单与分段，支持范围请求，避免Windows读清单时阻止替换。无需引入Rust/Tauri或浏览器播放器。

新录播共用playlist.m3u8：录制中EVENT保留已录历史，停止/轮转后VOD及ENDLIST。增长/定位不再重建播放器；导出冻结VOD输入及选区，仅处理相交片段，保留原有快速复制/精确编码的选择。已有EDL录播作为只读兼容入口保留，不修改原文件。

本轮不照搬对方的自动录制所有房间、Web界面或默认转码参数，不加入多轨/投稿/热度分析；原按钮录制 → 内嵌回看和时间轴 → 后台切片，是本轮实际范围。未复制对方具体代码，来源用于架构学习。
