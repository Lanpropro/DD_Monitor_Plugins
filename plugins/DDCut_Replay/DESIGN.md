# DDCut Replay 首版设计

状态：2026-11-04 开发方案；流程和范围为本任务的实施选择，尚未经过用户人工验收。

## 目标与范围

从画面墙录制或缓存进入专用工作区，找到录像、独立回看、设置单个时间选区、后台导出并找到成品。保留本体录制、原始流直存、快速保存、画质锁定和退出收尾。

本轮不实现多轨工程、自动热度分析、AI、字幕或投稿。不迁移已有录像，不改写播放后端。

## 使用流程与页面

左侧底部统一操作区“录制切片”和 Ctrl+Shift+R 打开工作区；格子右键可定位当前路。工作区关闭只停止预览并释放素材占用，后台任务保留；重新打开可查看。

| 页面 | 看见什么 | 主要操作 | 状态与空态 |
| --- | --- | --- | --- |
| 录制中心 | 画面墙房间、录制/缓存/收尾状态 | 开始/停止录制、启停缓存、快速保存、打开回看 | 未设目录可打开本体录制设置；无房间提示先加入画面墙 |
| 录播档案 | 本体目录中的录制/回放成品、导入录像 | 刷新、导入、回看、打开文件位置 | 不扫描账号数据；不提供删除原录像 |
| 回看与选区 | 素材标题、可读范围、播放器、起止与标记 | 播放暂停、定位、I/O 设置边界、M 标记、导出 | 活跃录制只使用已封口分段；刷新后才扩展当前回看范围 |
| 任务中心 | 正在处理和本次运行的历史任务 | 取消、打开成品/目录、返回素材 | 失败保留说明；重启后未完成任务显示中断，不伪称续跑 |

Qt 原生控件、系统字体、继承本体调色板；视频区固定深色。QSplitter 分配预览与检查器空间，表格按可用宽度伸缩。动作均有文字、键盘焦点与禁用原因；状态同时以文字显示。常用控件至少 28 逻辑像素，最小工作区 920×600；布局需离屏检查 100%/150% 与深浅色，不把自动布局检查当作人工视觉验收。

## 模块及宿主边界

源码路径保留 `plugins/DDCut_Replay/`，运行时 ID 选为 `ddcut_replay`。清单 ID 管理 ZIP 顶层与安装目录；构建器以源码目录查 Git 跟踪文件，将内容映射至清单 ID，不改用户指定目录。

| 归属 | 职责 |
| --- | --- |
| 本体 RecordingManager | 原录制与缓存、FFmpeg 录制进程、快速保存与收尾；新增分段租约供插件使用 |
| 本体 PluginContext.recording | 只读来源/状态快照、通过 CaptureControl 发起操作、获取/释放可读分段；停用后拒绝新操作 |
| 插件 media.TaskHub | 扫描本体成品与显式导入、选区/标记持久化、记录来源和时间范围 |
| 插件 media/tasks | 工作线程探测、构建回看副本、FFmpeg 导出与进度、取消和原子提交成品 |
| 插件 workspace | Qt 工作区、预览、选区和任务反馈，不直接读写主窗口私有字段 |
| 插件 plugin | 全局入口、格子菜单、工作区和任务生命周期 |

录制生命周期：CaptureControl 校验设置/画质 → RecordingManager 获取独立流 → 10 秒分段 → 排除未封口尾段 → 正常停止/轮转后合并 → 保留回放或清理。插件通过桥接获取一次快照并占用对应分段；后台生成稳定回看文件后释放占用。用户刷新时取得新快照，不假装时间轴实时连续，也不将断流后的空白补成真实录像。

首版按回看副本内部连续媒体时间选区，原始房间/快照时间单独保留；不宣称断流段可映射为无缝墙钟时间。不同编码来源不强行拼成一条会话，失败时给出分段/编码提示。

## 导出与退出语义

- 快速复制保持原编码，选区可能按关键帧扩展；不能标为逐帧准确。精确剪辑用 H.264/AAC 重编码，耗时和画质变化明确显示。
- 耗时探测、合并、编码在工作线程；GUI 只提交操作和轮询已缓存状态。FFmpeg 无控制台、后台优先级。
- 输出写入任务专属临时文件，成功并确认可读才原子移动至新成品；取消/失败只清自己的临时文件，不覆盖旧成品。
- 预览默认静音。关闭窗口停止播放器；导出继续。插件卸载/退出取消插件任务并回收子进程，再释放分段租约；本体原录制按既有流程收尾。
- 预览副本和任务状态使用插件数据目录；标记只保存元数据，不移动原录像。任务日志不保存直播 URL、凭据或 Cookie。

## 验证及阶段

1. 桥接与构建映射：本地替身验证停用边界、未封口尾段排除、缓存淘汰占用保护、安装 ID 及包内源码一致性。
2. 可安装首版：本地静音媒体验证预览、边界、两种导出、取消、旧成品保护、窗口关闭重开、任务中断说明；截图检查深浅主题和高 DPI。
3. 本体录制/退出原回归；集成到根目录后通过普通 run.cmd 入口复测，隔离数据和插件、不联网、不抢前台。无法隔离的真实入口验收交由用户手动执行，不擅自重启真实程序。
4. 人工确认真实直播、长时间运行、听感与 DPI 后记录验收；不自动发布。

宿主桥接提交 `3421ccb`（function/ddcut-replay-host），插件单独提交；仅版本号不足以证明未发布桥接已经存在。


## 底部入口落地（2026-11-04）

按用户后续选择，工作区与下方账号、布局/设置、导入关注/添加直播间连接为同一个底部容器，共用连续底色，不再将工作区单独围成方块；右上角开关可将整个底部操作区向下收起，底边保留展开把手。保持原有按钮顺序、录制独立窗口与比赛二路切换方式。通过宿主 register_workspace_control 统一归属、主题和位置；无活动入口时隐藏工作区。收起时用图标，竖屏跟随顶部横栏，回横屏归还原底部区域。


## 最新交互修正（0.1.2）

用户明确要求只收起功能区，账号/布局/导入/添加固定可见。本轮将收起容器缩到录制与比赛入口，保留同一连续底色。录制切片改为普通 QWidget 嵌入主内容区，替换画面墙显示，不再作为独立窗口；返回恢复原内容，后台任务继续。通过宿主 show_workspace 协调与比赛二路互斥，保留比赛原嵌入/播放/关闭流程。此条替代前版“整个底部操作区收起”及独立窗口方案。
