# ShadowReplay 功能对照与当前边界

核对日期：2026-11-05。参考固定源码 `e340951fa500d3977f5b9981329a1939650da82f`（2.25.1）及用户提供的实际界面；不是对参考项目未来版本的保证。“已实现”指开发候选中有实现和自动功能验证，真实直播与人工验收仍待完成。

此前只概括了录制、回看、切片，没有完整区分素材、剪辑工程及弹幕链路；此表补齐遗漏。2026-11-05用户提出先对齐参考功能、再做定制，随后明确暂缓AI、自动化与内置素材库，素材管理准备接入其他软件。当前分批范围与验收见[对齐计划](PARITY.md)。下表保留参考能力对照，暂缓项不计入当前必须完成的范围，也不标为已实现。

| 字幕 | Whisper/云端识别、缓存、手动打轴、样式、SRT/压制 | 尚未实现；本阶段保留手动打轴、SRT导入导出、样式与压制，AI识别暂缓 |

| 投稿与封面制作 | B站投稿草稿/上传/重试、双比例封面、文字与贴纸 | 尚未实现；账号、关注和发送弹幕继续由本体/现有平台插件负责 |

| 自动化与AI | AI助手查询/分析字幕弹幕、MCP外部调用、Webhook通知 | 用户明确暂缓；现有弹幕热度为本地数量统计，继续保留 |
| 额外输入与部署 | OBS RTMP接收、浏览器深链、Web/headless/Docker | 尚未实现；当前是本体内嵌Qt插件 |
| 总览与管理 | 缓存/磁盘/时长概览、房间状态与录播日历等管理入口 | 尚未做对应的插件管理页；本体已有空间检查/录制设置继续复用 |

执行顺序：多选区/批量导出 → 完整弹幕链路 → 外部文件与剪辑工程 → 手动字幕与高级导出 → 投稿/封面 → 其他输入与部署 → 管理与完整流程回归；具体完成标准见[对齐计划](PARITY.md)。暂缓AI、自动化与内置素材库，现有账号、关注和录制入口继续复用本体。

## 本轮亮点功能怎样使用

1. 没有活动录制/缓存时开启“仅录制切片素材”，使用原格子按钮开始新录制；本体需要已连接该房间的弹幕。
2. 从录像页打开素材，点击“弹幕亮点”；可读录像满30秒后显示热度和候选区间，约每2秒批量更新。
3. 默认阈值是当前录像最高30秒窗口数量的80%，可调50%～100%。它不是“亮点置信度80%”；观众少、刷屏和剧情延迟都会影响结果。
4. 关键词用中英文逗号分隔，按“任意词匹配”统计；输入后回车或移开焦点生效。阈值和关键词随该录像保存在插件状态中。
5. 点击推荐设为入出点并定位回看，确认内容后可调整边界、预览选区，再用“选区”里的原导出操作生成视频。不会自动导出、删除或投稿。
6. 旧档案、导入视频、原版单文件没有弹幕记录时明确显示空态，不根据画面或文件名猜造热度。新归档需要一起保留 `danmaku.jsonl`、`recording.json`、清单和分段。

本轮只记录本体传来的普通文字弹幕，不保存账号凭证、观众ID或额外发起弹幕连接；本体屏蔽词过滤后的消息才会进入统计。断流等待期间的消息不会映射到无视频的区间，未封口尾段等视频可读后再纳入。
