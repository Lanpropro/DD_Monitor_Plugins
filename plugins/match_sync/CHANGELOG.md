# 比赛二路同步 · 修改版更新日志

本文件只记录本 Fork 维护的 `match_sync` 修改版。原作者的版本历史见 [`docs/releases/`](../../docs/releases/README.md)；
上游 `1.4` 及更早的说明保留在上游仓库，不在此复述。

版本号独立于上游序列：修改版以作者 `1.5` 为基线，从 `1.5` 起按语义化版本递增（见 [`docs/versioning.md`](../../docs/versioning.md)）。

## 待发布

暂无。

## 1.11.0

**新增**

- 画中画增加「自动框选」：一次性在副直播间画面里识别摄像头窗口，直接把小窗裁剪区域设成识别结果。
- 开启画中画时自动尝试一次（延迟 1.2 秒，仅当裁剪区域仍是整帧）；识别不到保持原状，不影响手动「框选画面」。

**改进**

- 手动「框选画面」松手后四条边自动贴合最近的画面分界（搜索范围是画面的 4.5%），修掉拖框时常见的多裁 / 少裁几像素。
- 自动框选的结果也会做一次贴合，避免识别框正好压在线内或线外。

**变更**

- 移除 1.10.0 的「自动跟随摄像头」与 1.5 秒周期跟踪：摄像头窗口通常一个赛事只挪一次，持续跟踪的意义不大，改为按需一次性框选。
- 识别改为多分辨率（640×360 / 480×270 / 320×180）择优，优先按四条边的配对关系找独立窗口，没有矩形时用 OpenCV 人脸框兜底（同一张脸需在两档分辨率上都被检出）。

**兼容性**

- 只依赖 NumPy；没有 OpenCV 时仅失去人脸兜底，边框检测照常工作。
- pip 设置里不再保存 `follow`，旧配置里残留的该键会被忽略。

## 1.10.0

**新增**

- 画中画新增「自动跟随摄像头」：勾选后插件自己在副直播间画面的缩略图上识别摄像头窗口，按 1.5 秒的节拍把小窗裁剪区域移过去，主播挪动摄像头位置时小窗跟着走。
- 识别以当前框选区域为起点，先用上一帧的裁剪内容做模板匹配跟住窗口；跟丢后再按边框与内部画面差异重新找窗口；两者都没有结果时沿用上一次的裁剪，不闪回整个画面。
- 取消勾选立即回到手动框选；手动重新框选会清掉自动结果，不会与识别互相打架。

**修复**

- 自动识别只在本地 320×180 灰度缩略图上做，不额外拉流，不影响声音混合、时间对齐与自动匹配（对齐仍使用完整画面）。

**兼容性**

- 需要宿主自带的 NumPy（`requirements.txt` 已声明 `numpy>=2.2,<3`）；没有 OpenCV 也能运行，人脸只作为兜底线索。
- 画质按钮、声道按钮、分隔条与对齐行为不变。

## 1.9.2

**修复**

- 分隔条拖动改由插件自己处理：按下时记录光标横坐标与当时的左右宽度，移动时按像素差直接设置两栏宽度，不再让 `QSplitterHandle` 用子控件的最小宽度做约束计算。
- 主画面栏与弹幕栏各自只声明 140 像素的最小宽度提示（`PaneHost.minimumSizeHint()`），弹幕列表或发送台内容再宽也不会抬高整栏地板——这是「往右拖却往左跳」的直接原因。
- 分隔条手柄改为水平分隔光标；释放后 220ms 才重新计算内部布局，拖动过程中不重排。

**兼容性**

- 画质按钮、画中画与自动对齐行为不变。

## 1.9.1

**修复**

- 左右面板不再各自保留 420/320 的隐形宽度下限，分隔条可以一路跟随光标拖到最窄。
- 按下分隔条的瞬间就冻结两侧重排（监听分隔条自身的鼠标按下/松开，而不是等第一个移动信号），第一个像素不会再触发发送台的宽窄切换。
- 弹幕栏窄到放不下输入区附属按钮时只隐藏这些附属按钮，不再反过来把面板撑宽；发送台声明可压缩到 200 像素宽。

**新增**

- 双击分隔条恢复默认宽度（约为可用宽度的 42%）。

## 1.9

**新增**

- 下方控制台为每一路新增画质按钮，直播间之间互不影响，换档不必再切到主画面。
- 左键循环该路可用档位，右键直接选择；换档只重启这一路，其余路继续播放。
- 画质档位随设置保存，重启后沿用；取流后按平台返回的实际档位刷新按钮文字。B 站房间同样按当前编码与登录状态查询可用档位，不是写死清单。

**修复**

- 拖动弹幕栏分隔条时的回弹：拖动过程中不重排控制台，松手后才重新计算布局。
- 分隔条两侧保留最小宽度并记住宽度，弹幕栏可以拖回原来的位置。

## 1.8

**新增**

- 以作者发布的 `1.5` 为基底重建，保留其整组回看、弹幕发送台、区域匹配、面板拆分等全部新功能。
- 画中画改为主画面内的可拖动小窗：自由拖动、右下角等比缩放、窗口缩放时自动收回画面内、全屏时保留；位置与大小随设置保存。
- 画中画小窗不画强调色边框，静止时无额外装饰，悬停或拖动时才显示右下角握把。

**修复**

- 「原始声道」下拉改为点按循环 原始 → 仅左 → 仅右，右键可直接选择，不再依赖弹出菜单。

## 1.7

**优化**

- 画中画小窗去掉蓝色描边，边缘不再有高亮框；右下角缩放手柄只在悬停或拖动时出现。

> 历史 Release：`1.0.0-alpha`（资产 `match_sync-1.7.zip`）即为该版本。正文见 `docs/releases/RELEASE-match-sync-v1.7.md`。

## 1.6

**修复**

- 修复画中画「框选画面」不生效（框选后仍显示整幅画面）：画布把框选区域存成 Qt 的 `QRectF`，几何模块按顺序解包时抛异常并静默回退成整帧；现统一用普通数值元组，并让几何模块兼容 `getRect()` 形式的矩形。
- 去掉「位置」下拉与「大小」滑块，改为在画面上直接操作：拖动小窗移动，右下角出现斜向双箭头时拖动缩放。
- 小窗位置与大小随插件设置保存（`rect` 归一化坐标），主画面比例变化时自动收回画面内并保留最小尺寸。

## 1.5

**新增**

- 画中画：把某一路的框选区域（例如二路解说的人脸）按原始比例叠在主画面内，主画面保持清晰。
- 设置栏新增一行：勾选「画中画」、选择来源路、「框选画面」选择区域、「位置」选角、「大小」在 10%–45% 之间调整（默认 28%）。
- 来源路保持全分辨率取帧，不因画中画缩小成分析尺寸；关闭画中画或移除来源路后立即清空，全屏主画面时保持显示。
- 框选区域按该路保存，与「选择对照区域」互不影响，重新加入同一房间时沿用。

> 后续 `1.6` 起「位置/大小」控件被画面内拖动与缩放取代，本条保留当时的实现记录。
