# 比赛二路同步 v1.7.0.2

## 二路弹幕观看设置

播放器的弹幕设置按钮及右键「弹幕观看设置」直接打开二路独立面板。显示区域、不透明度、字号、速度、描边和随屏幕缩放在插件内保存，首次使用当前主程序参数初始化；之后不跟随全局修改，也不反向修改主程序。颜色始终由下方控制台每路颜色选择控制，不提供统一颜色、缩放曲线或全局/独立切换。普通主程序画面格设置和SC设置不受此项影响。

## 计时器辅助对齐

点击各路「偏移」组中辅助自动对齐右侧的计时器图标，选择正计时或倒计时，分别框选各路相同的游戏计时器，再点击「采样并识别」。展开「偏快／偏慢」时计时器图标向右避让，收起后回到原位；不改变其他路偏移或控制台高度。对照微调顶部不再重复显示计时器按钮。获取成功后先显示画面缩略图，框选后显示选区缩略图；采样后窗口展示约1.5秒的缓存画面；首帧固定作为读数基准，选中第一次数字变化后的画面。Windows 本地 OCR 会建议首帧读数与翻秒帧，识别不出时可手填 `分:秒` 并手选画面。

核对后点击「计算偏移」，查看相对主画面的建议及采样边界误差，再点击「确认应用」。计算不改变播放，确认后复用现有手动偏移，同时调整画面、声音和弹幕，并关闭自动匹配以保留手动结果；可重新开启自动对齐。未参与的来源保留当前偏移。各路框选单独保存，不改变原有对照裁切或自动匹配区域。

此方法要求同一局、同一回合、同一个持续运行的游戏时钟。主播电脑时间、独立技能倒计时不能用于对齐。暂停、回看、变速、换源、换主路或采样后偏移变化时，须恢复正常播放并重新采样；回合重置、时钟停走或识别不确定时不要应用。误差是采样边界估计，不是实际显示同步精度保证。

只在明确操作时从现有视频缓存后台取帧，不额外拉流，不持续运行 OCR。Windows OCR 使用系统组件与临时的计时器裁切图片，任务结束或取消后删除；不联网、不读取账号、不保存直播画面。缺少系统 OCR 时仍可手工操作。真实直播与低配置实机效果尚待人工验收。

`1.7.0` 已作为基于公开 1.6.1 的版本发布，包含计时器辅助对齐、对照微调布局、全屏控制、播放恢复和界面职责拆分；保留功能中心入口与旧版底部入口。

实验：全画面匹配失败时，自动寻找两路共同游戏区域。先用局部特征和几何一致性排除边框、聊天区、立绘、
时钟及小范围标志，再用区域内的连续动态画面验证时间差；不读取计时器、不复用或恢复旧的「选择对照区域」同步方案。
适用于同一过程被不同布局包装，或合作游戏中确有共同场景变化的画面；静止、重复场景及独立动作不足以自动对齐。
没有可靠证据时继续等待，不强制应用偏移。通过的区域会缓存供后续复核，切换主画面或布局变化时重新定位。
每路只增加最多 60 秒的低分辨率灰度样本（约 12 MiB），区域搜索在既有后台匹配任务中进行，不启动新直播连接。
仍需用实际直播验收，合成测试通过不代表所有合作游戏视角都能同步。

每路控制区新增「裁取悬浮画面」。框选副路摄像头等区域后，在软件窗口内生成一块独立悬浮画面，
可覆盖画面、侧栏和弹幕等区域，不受主画面格子边界限制。拖动画面移动，滚轮或右下角等比缩放，
双击重新框选，右上角关闭；不同主播可各保留一块。右下角缩放使用连续等比计算，斜向拖动跨越横纵方向时不会突然跳变。软件缩小时自动将悬浮画面约束回可见范围。
全屏时跟随到全屏窗口，退出后返回软件内。移除来源、停止观看或关闭插件会清理悬浮画面。
悬浮格采用与画面格一致的圆角；左上角仅显示来源主播头像，关闭键保留在右上角，鼠标移入显示、移出隐藏，不额外占用画面上方空间。
圆角采用抗锯齿透明边缘，画面填满边界，避免整数遮罩在屏幕缩放时产生锯齿及右侧边缝。
移动、缩放及关闭后恢复原位置背景；悬浮画面使用普通子控件重绘，不使用关闭背景恢复的窗口透明属性。
画面直接使用已有解码器的原分辨率帧裁切及平滑缩放，不从低分辨率格子截图；后台副路仅在需要时启用原图解码，
复用原有缓存预算，不新增直播连接。保持原声音和对齐方式；直播/整组回看跟随对应来源时刻，暂停时保留当前画面。
悬浮画面关闭键左侧提供三态定位图标：随意移动、锁定在主画面格子内（包含留黑及底部控制栏）、锁定在当前位置。固定位置时禁止拖动和缩放，仍可解锁、重选及关闭；窗口缩小时保持可见。

每路声音组提供独立播放图标：不等待画面匹配，按本路缓存进度播放，保留声音开关、音量和声道；再次点击循环箭头恢复自动对齐。主路及其他副路保持原进度，独立播放期间该路不参与自动匹配，停止或重新开始后恢复普通对齐流程。

悬浮区域独立于「对照区域」。框选窗口支持 Ctrl＋滚轮按指针缩放、滚轮上下平移、Shift＋滚轮左右平移；顶部仅显示快捷键。

主画面默认按平台提供的顺序从最高档开始取流，不可用则自动尝试下一档；列表获取失败时尝试原档位。切换主路会为尚未使用该策略的来源重新取流一次，副路画中画仍遵循原均衡策略。取流成功不保证网络带宽或硬件一定能流畅播放。
主动选择 HDR、2K 或其他档位后保存手动选择，切换主路仍保留该选择；自动尝试下一档只用于默认最高画质策略，显式指定档位失败仍提示连接失败。

比赛二路控制台的齿轮设置提供「画中画画质」：

- 流畅优先：直接裁切摄像头区域并平滑缩放，默认启用。
- 轻量增强：只对摄像头选区做 Qt 平滑缩放和 NumPy 限幅轻锐化，在后台 CPU 线程处理，兼顾无独显设备；不需要模型或额外 GPU 运行时。

两种模式共享同一来源，副路优先720P，否则按平台列表选择中间档；主观看画面不因此降档。
首次创建或关闭画中画可能因切换来源档位重新缓存和对齐；两种处理模式之间切换不重连直播流。
旧配置的「最高画质」迁移为流畅优先，「局部超分」迁移为轻量增强。

每块画中画最多一个执行中任务和一个可替换待处理帧。增强结果与对应的原始帧成对显示，
迟到结果不使画面倒退；原始像素与增强图使用相同的分数像素选区，避免边界取整导致位置变化。
初始化期间显示普通画面。滤镜线程实际CPU开销（最近32帧均值）连续八次超过来源帧预算的125%（最低预算10ms）、
GUI持续正常轮询但后端500ms没有新结果、选区超过230400像素或后端不可用时，本次观看保持普通缩放。
GUI超过50ms的停顿不计入后端无进度时间，落后来源80ms的结果只丢弃，不因此永久回退。
锐化使用四邻域差分，单通道增减上限10/255；不进行强去噪或人脸重建。
切换到流畅优先后再选择轻量增强可重试。设置窗口显示增强、回退原因及准备中的路数。
回退事件写入宿主日志；播放诊断中的`surface.floating`记录对应状态、原因、实际CPU/总耗时及来源/显示时间戳。
这是轻量插值和锐化，不是神经网络超分，也不保证恢复来源丢失的真实细节。
后续后端可实现 `LightScaler.upscale(QImage, QSize) -> QImage` 接口，复用队列和显示时序控制。

有直播间时，格子底栏音量右侧常驻播放进度条，占中间空位约三分之二并居中留白，不设置重放开关。
进度条下方显示窗口起点、中点和终点时间，拖动时额外显示与进度条等长的竖线刻度（每秒一格、每五秒标时）和毫秒读数；刻度下衬半透明深色底，浅色文字及竖线在明亮画面上仍清晰。右侧显示可编辑的已播放时间，以当前回看窗口起点为 00:00，

v1.5 优化 4K 解码、图像转换和皮肤重绘；改善多路匹配持续失败时的界面响应，避免界面读取音频时钟时等待混音锁。二路全屏使用无边框窗口并向 Windows 标记全屏，退出后撤销标记。独立设置进程由本体提供，不包含在此插件升级中。

本版本兼容 libmpv 宿主：PCM 左右声道路由由插件内部实现，保留 C 实现及纯 Python 回退，
不再依赖宿主的旧 `ddm.audio_output.route_pcm_s16_stereo`。同步、缓冲及界面功能保持此开发版实现。

用于 B 站及已启用平台插件的多位主播观看同一比赛时，选择其中一路作为主画面，同时听多位主播的声音并合并弹幕。

当前主路策略：正常情况下由副路对齐主画面；已验证的副路持续晚到时，可通过最多约 2% 的轻微降速平滑积累共同缓冲，不暂停或跳转主画面。超过平滑追赶能力时，在「对照微调」右侧提示具体过慢直播间并建议更换主画面。此策略替代下方历史版本说明中绝不因副路增加延迟的限制。

可在设置栏右侧选择「低延迟 · 2 秒 / 均衡 · 5 秒 / 抗波动 · 8 秒」，默认 5 秒。已验证副路的连续可播放余量持续低于目标时，即使仍在播放，也会轻微降速补充共同缓冲。目标附近保留约 0.5 秒触发余量和恢复冷却，避免反复调速。高档位需要数分钟逐步积累，额外缓冲不沿用旧版固定 4 分钟期限；实际追不上副路时仍提示更换主画面，容量不足则单独提示。暂停、未匹配、过期和断流缺口不参与补充。降低档位不跳转画面。此策略替代历史版本中固定 2 秒余量的说明。

当前对齐流程：自动匹配始终使用完整画面；「选择对照区域」只用于放大计时器或其他共同内容，方便人工微调偏移。框选不再改变自动匹配区域、清空样本或触发重新对齐，旧版已保存的框选也只影响预览。不再显示「辅助自动对齐」入口。下方历史版本的区域匹配和人工辅助搜索说明仅供追溯。

## 分音轨录制

二路控制台齿轮中的「录制音轨」按 OBS 式矩阵为每路选择 1～6 的一条或多条音轨。
同一音轨混合所有勾选的来源；不勾选则不录该路声音。新来源默认分配尚未占用的音轨，
六条都被占用时新来源默认不勾选；重排和切换主画面不会自动改动其他来源的录制音轨。
例如所有来源勾选 1 作为完整混音，再各自勾选 2、3 等作为独立音轨，便于后期分别选择。

二路控制台齿轮中的「录制格式」可选 MKV（默认）或 MP4，录制期间锁定。
MP4 需要正常停止录制完成文件；长时间录制可使用 MKV。
主画面底栏的录制按钮保存一个所选格式文件：主画面原视频编码复制，所选音轨为 48kHz 双声道 AAC，
包含音轨编号和来源名称。录制复用已有视频与 PCM 缓存，不额外取流；从当前进度之前最近的可用关键帧开始。
录制保留来源的原始立体声，不受收听静音、音量或 L/R 影响；未对齐或缺失来源写入静音。
画中画、界面和滚动弹幕不烧录进视频。使用主程序设置的录制目录及剩余空间下限；
二路多音轨使用此处选择的容器和原编码，不套用主程序的其他输出格式、转码及分段设置，普通画面墙录制保持原行为。

录制期间音轨矩阵锁定。再次点击录制、添加/移除来源、切换主画面、跳转回看或停止二路会结束并收尾当前文件；
换档/重连导致主视频缓存重建时也结束当前文件。结束后可调整音轨再开始。
普通播放器可能仅播放其中一轨，按音轨编号选择；剪辑软件可分别使用各条音轨。

## 安装与入口

1. 源码版先更新 `requirements.txt` 的依赖（PyAV 和 NumPy）；EXE 版需要包含这两个组件的新版完整程序。旧 EXE 仅替换插件无法增加原生解码组件。通过「设置 → 插件 → 装载插件」选择 `match_sync-1.7.0.2.zip`。
2. 保存并重启这一份程序；插件卡片应显示「比赛二路同步 / 1.7.0.2 / 已加载」。
3. 新版关注栏点击「功能中心 → 比赛二路」，可搜索并固定为常用入口；顶部横栏同样通过功能中心打开。旧版主程序继续使用关注栏底部或顶部的比赛二路按钮。关注栏保留，右侧观看区域切换为主画面与合并弹幕。
4. 将左侧关注栏卡片拖到右侧观看区域；第一路加入后自动开始，再拖其他卡片加入更多直播间。点击下方设置栏每位主播名字旁的「主画面」按钮选择想看的主播画面，「自动对齐比赛画面」也在同一栏。
5. 每个副路首次匹配成功后，打开对照检查比赛进度，点击该路「确认对齐并加入」；若先微调偏移，则点击「确认微调并持续同步」。确认前副路静音。已经确认的路遇到短时缓冲后自动复核恢复；缺少同步内容的副路先静音，持续晚到时按当前主路策略平滑建立缓冲，无法追赶时提示更换主画面。
6. 再次点击「比赛二路」按钮关闭模式，停止插件取流与混音，返回原画面墙。同次启动关闭再开启保留参与房间，重新取流并清除暂停状态；重启程序后参与列表为空，旧测试房间不会自动加入。重新拖入同一房间可沿用该房间的调节值。

虎牙、斗鱼、抖音等平台需先启用对应平台插件，沿用其公开直播流、画质与弹幕能力；完整多平台弹幕需使用包含该平台弹幕组件的主程序。仍通过关注卡片拖入；独立窗口也支持平台前缀（如 `huya:房间号`）或官方直播链接。

已有旧版时，安装器不支持同 ID 覆盖安装。退出程序后，将新 ZIP 内 `match_sync` 文件夹的文件覆盖到这份程序的 `plugins_user/match_sync/`，再重启；配置文件无需改动。

本仓库发布源码位于 `plugins/match_sync/`，使用 `python tools/build_plugins.py` 打包；ZIP 顶层目录为 `match_sync`。

## 调节

- 播放栏弹幕设置菜单中的「更多弹幕设置」打开主程序的弹幕设置页；保存后同步更新二路画面弹幕与右侧弹幕面板。
- 各路下方以单行图标摘要显示连接、对齐、独立播放、静音和可播放秒数；悬停每个图标或对应短文字时，仅显示该项说明。缓冲图标说明包含历史缓存和前方可播放时长；未验证的候选余量不作为可播放秒数显示。「对照微调」固定紧邻「自动对齐比赛画面」右侧。
- 新加入直播间的初始音量沿用「设置 → 新建格子的初始音量」；已有房间保存的音量优先，修改此设置不会改变正在播放房间的音量。
- 右侧弹幕贯穿观看区域全高；各路设置仅占左侧视频下方的无边框滚动栏，拖动分隔线可调高度。每路控件按主播选择、声音、弹幕、偏移、画面区域和移除分组横向铺满面板，组内保持紧凑单行；宽度不足时可横向滚动。音量条旁显示 0–100 的实时数值。右上角「最小化」收起整个设置栏，左侧视频区域底部的「展开设置」恢复原有高度和调节值，期间画面、声音与弹幕继续播放。每路独立启用声音、调音量、选择声道、启用弹幕。拖入第一路自动开始。
- 设置栏顶部两角与上方播放栏统一为 8 像素圆角，底部保留 12 像素圆角及半透明深色渐变底，控件采用 8 像素圆角与半透明填色。原 Tile 按钮保留本体圆角样式。
- 各平台的二路弹幕在右侧列表的昵称前用 `【主播名称】` 标注来源直播间，并采用该路预设颜色。画面上的滚动弹幕已有来源颜色时只显示正文，无来源颜色时保留主播名前缀；直播和回看规则一致。现有粉丝牌数据缺少所属主播信息，无法可靠区分其他主播的牌子，因此二路面板不显示粉丝牌，也不虚构等级；仅修改显示副本。
- 移除最后一个直播间时立即清空画面和弹幕、停止取流与混音，不保留最后一帧；再次拖入任意支持平台的卡片自动开始。移除或重连后重新获取直播地址。
- 声道可选「原始声道 / 仅左输出 / 仅右输出」；仅左或仅右会将这一路的完整声音混为单声道再送到相应耳机一侧，切换即时生效。
- 声道直接用 L／R 两个按钮切换：两侧点亮为双声道，只点亮一侧则输出到对应侧。两侧关闭时静音，点击任一侧恢复；与原声音按钮联动，历史声道配置及 E 快捷键保留。
- L／R 蓝底只表示该侧已开启，关闭侧悬停使用中性灰；控制台按钮不再因点击焦点残留蓝色底。
- 声道由用户手动选择并记忆，不按路数自动分配；原有 E 声道轮询快捷键保留。
- 播放控制台使用统一的默认高度，空台和新增主播不会改变高度，多路通过滚轮查看；手动拖动分隔线仍可调整高度。拖动卡片时，其余卡片以短动画让位，关闭系统动效时直接换位。弹幕发送台沿用播放台的工具栏和悬停反馈，原平台发送、草稿、多选、表情和礼物功能保留。
- 声音、弹幕、重对齐及设置复用宿主控件；焦点与选中使用底色和图标反馈，不画蓝色虚线框。点击当前弹幕颜色展开横向色板；卡片末尾直接移除，保留五秒撤销，不再提供修改主播名称菜单。
- 偏移右侧点击辅助图标，在图标右边展开「偏快／偏慢」，选择后收回并使图标进入等待状态；本路新一轮完整搜索结束后才能再次展开。展开预留位置，控制台与其他按钮不跳动。判断作用于完整画面搜索、精校正及共同区域候选的排序，不直接修改偏移或提高视觉置信度。样本不足、匹配异常、过期或取消的任务不会提前解锁。同方向重复判断逐次增加权重（最多四次），改方向重新计权。保留原连续画面、共同区域与多路一致性验证；没有可靠证据继续等待。切换主画面、手动重对齐、关闭自动对齐或重启来源会清除旧判断；提交与完成结果写入普通日志，便于真实观看复验。
- 横向色板在显示前完成尺寸设置，避免首次展开出现大菜单后再缩小；发送台主播选择与编辑发送区域之间使用竖线分隔。窄窗下控件换行，控制台高度与滚动规则不变。
- 主画面复用原画面格按钮：悬停右上角选择画质、刷新或移除，下方调音量、静音、暂停/继续、全屏与录制。画质选择重新获取该房间对应档位的流，期间显示原有缓冲动画，收到可播放帧后自动收起，不显示空房间的拖入提示；不会重启其他房间。暂停只冻结并静音主画面这一路，其他房间继续；恢复时返回当前对齐进度。录制保存主画面原编码视频与矩阵中所选音轨。画面格静音与设置栏的声音开关双向同步；音量数值也同步更新。按 F（或本体配置的放大快捷键）进入或退出二路主画面全屏，退出恢复视频与设置栏的分隔位置；编辑主播名称时不触发全屏。左上角仅保留 LIVE 和主画面直播间标题，不显示获取人数提示；未收到标题时暂用主播名称。
- 来源颜色只提供蓝、粉、紫、绿、黄、橙六种预设；界面和弹幕来源标签不显示房间号。开启二路时隐藏原布局的蓝色观看标记，正在由二路取流的关注卡片改用粉色边框；竖屏头像条同样隐藏旧标记并加粉框。移除或停止取流即取消粉框，退出二路恢复原布局标记。
- 右侧弹幕和主画面「弹幕」开关共用所有已开启弹幕的直播间，来源统一为「【主播名称】」。单路关闭弹幕即停止该路连接，重新开启会重建连接；B 站临时连接失败自动重试。右侧批量消息按参与房间均分每次显示额度；画面滚动弹幕按来源轮流分配轨道，每路最多暂存一条最新消息，超过 5 秒的等待消息丢弃，避免某一路集中到达时挤掉其他来源。缩放或改变字号后重新检查轨道间距，舍弃会重叠的后发弹幕。二路使用 Qt 浮层绘制，不使用原生 VLC 浮层，避免遮黑画面与残影。主画面滚动弹幕开启或关闭不停止视频、声音或右侧弹幕。
- 斗鱼取流使用软件已记住的斗鱼登录状态向官方接口申请画质，二路保留用户请求档位供重试，同时单独显示平台实际返回档位；账号不可用时仍如实显示实际档位。
- 偏移按钮正下方常驻小字说明（左缘与「偏移」对齐，窄屏可换行）：单位为秒，+ 正数延后本路，− 负数相对提前本路。鼠标悬停「+」「−」按钮也会分别弹出说明，涵盖画面、声音和弹幕的作用。
- 「播放偏移」同时调节该路画面、声音和弹幕：点击「+」延后、点击「−」提前，步进 0.1 秒，也可直接输入。负偏移会相对提前本路；超出基础缓冲时，系统同时延后较快的其他路，保证不读取未来画面或音频。实际缓存仍不足时会明确显示等待缓存。旧版弹幕微调值不再使用。
- 点击「对照微调」、进入偏移输入框或按「+/−」会展开对照画面。预览使用和声音相同的当前播放进度，不使用直播最新帧冒充播放帧。总计不超过四路时横向展示主画面与全部副路，窄窗口可横向滚动；超过四路时左侧固定主画面，右侧通过主播选择切换，点击某路偏移会自动选中该路。各路显示相对主画面的实际提前/延后秒数；可勾选「放大框选区域」查看计时器。点击右上「收起对照」或取消「对照微调」隐藏预览，保留所有偏移并继续播放。查看对照继续自动匹配，实际修改偏移才锁定为手动控制。点击「最小化」同时收起对照面板。
- 自动同步先用每秒 5 份画面特征粗匹配，再用每秒 20 份特征精校正；精校正在候选附近 ±1 秒内以 25ms 步长搜索，并用实际样本时间细化。连续两次一致的结果才应用；界面区分「正在确认精校正」「已应用精校正，待复核」和「播放进度已复核」，复核后显示估计剩余误差。安全余量初始为 6 秒，并在 4～8 秒之间调整；主画面开始正常播放后固定其基准，副路晚到超出当前缓存时需要确认增加观看延迟后加入。
- 需要人工细调时，点击该路「选择对照区域」，框选同一计时器，放大对照后使用偏移的 +/− 按钮或输入框微调。弹窗冻结当前显示帧；未显示房间使用共同播放进度取帧，不用最新直播帧冒充。框选只影响对照，不改变播放、自动模式、已确认偏移或后台完整画面匹配，也不会读取计时器数字。
- 静止画面、不同比赛、遮挡、切场景、重复回放等可能无法判定时间差。界面显示匹配确认与播放进度复核状态；失败时保持上次确认的偏移，可关闭自动同步并手动调整。
- 点击「比赛二路」关闭模式，停止取流、弹幕与混音，并恢复主程序当前的静音设定。二路期间原画面墙隐藏，后台声音由插件接管，避免原生视频覆盖和重复出声；关闭后恢复原画面墙。重新开启会刷新远程流地址，不能沿用上一次已经过期的地址。

## 运行与资源

使用 FFmpeg、PySide6、PyAV、NumPy、本体 B 站弹幕组件及平台插件提供的弹幕客户端。源码需安装 `requirements.txt`，并从程序旁边或 PATH 找 FFmpeg；EXE 从其所在目录找。账户只沿用本体现有登录态，不写账号配置。

v0.1.15 的 Qt 画面弹幕透明绘制修复由配套主程序 `ddm/video_danmaku.py` 提供，需同时更新主程序源码；仅替换插件不会更新旧 EXE 内部的绘制实现。

v0.1.21 避免主画面每帧重复布局画质、静音及暂停控件，降低斗鱼 60 帧主画面的绘制开销。斗鱼弹幕先解析靓号对应的实际房间号，再登录和订阅，修复显示已连接却没有消息的问题；该弹幕修复由主程序 `ddm/live_danmaku.py` 提供，需要同时更新主程序源码，单独换插件不能更新旧 EXE 中的弹幕实现。

v0.1.22 的二路全屏沿用主程序的鼠标自动隐藏：鼠标在视频区域静止 3 秒后隐藏鼠标与控制条，移动时恢复；菜单、模态窗口或失去焦点时保持鼠标可见。F、Esc、停止二路或关闭窗口都会恢复鼠标与控制条。

v0.1.24 在进入二路模式时立即静音原画面墙全部播放器，不需要先加入房间或建立二路音频输出。空列表、停止二路播放、移除全部房间及本体播放器重连时仍保持原画面墙静音；关闭二路模式后按各格子的静音设置恢复，不修改其保存配置。

v0.1.25 首次主画面及切换主画面时默认请求平台最高画质，按平台档位排列选择，B 站包含高于 10000 的 2K 等档位；画质查询在解码线程内完成。已经处于最高档的流继续播放，其他房间不改档或重启。用户手动降档会保留，重新选择该房间为主画面时再次默认最高；平台因登录态或源限制返回较低画质时如实显示实际档位。

v0.1.23 优化首次匹配与误判：每秒两次图像指纹，最少收集 8 份；只比较双方都有变化的指纹位置，重叠的半秒候选桶聚合边界抖动，并以中位数剔除偏离超过 0.35 秒的配对。验证共同时间区间最后 8 秒内至少 6 个独立变化画面、一对一且时间顺序一致，覆盖至少 2.5 秒，最新支持距共同区间末端不超过约 1.5 秒。相距至少 0.75 秒的另一候选若评分达到最佳的 85%，拒绝判定。置信度至少 65% 且连续两轮一致才采用；每 3 秒检查一次。弱证据保留已确认偏移，手动锁定仍不受自动匹配覆盖。这是基于动态画面的估计，不保证逐帧精度；双方比赛画面位置/大小差异较大时，仍需分别框选共同区域。

v0.1.26 使用 FFmpeg 保留原始视频码流，PyAV 按真实 PTS 解码。主画面与对照保留实际片源分辨率和帧率，不再经过 720P/1080P 缩放、固定 30/60 帧或 JPEG 二次压缩；显示大小只在绘制时适配窗口。匹配只保存小尺寸画面特征；完整 RGB 图片由后台线程按播放时刻预取，界面线程只绘制。

v0.1.27 对真实 HTTP/HLS/RTMP 直播取消输入限速，及时读取 CDN 突发数据；本地文件仍按实时速度读取。原始视频与 PCM 音频放在同一个 NUT 管道中保留 PTS，使用共同的非负时间基准；以首份音频建立接收时钟，避免旧缓存关键帧把播放时刻锚到过去。PCM 按 PTS 写入环形缓存，时间空档静音，重叠部分不重复播放；收到音频基准前不发布未定位的视频时间。

v0.1.27 的精校正比较最近约 4 秒连续共同画面。16×16 灰度特征按亮度/对比度归一化，仅使用双方都发生变化的像素；NumPy 批量比较放在后台线程，避免大量 Python 循环争用播放时间。粗匹配保留最多 8 个相隔至少 1.5 秒的候选，逐个精校正；相近评分的多个时间差拒绝锁定。精校正要求至少 30 对、一对一且覆盖至少 80% 的参考样本，前后半段均需相似；置信度至少 65%，连续两轮差值不超过 0.15 秒才采用，每 1.5 秒分析一次。已确认偏移附近不超过 0.2 秒的小修正逐步应用；大幅变化重新确认。另按主画面实际显示帧及其他路当前播放时刻截取已播放样本复核，误差计入显示帧滞后；只有估计误差不超过 0.15 秒才显示「播放进度已复核」，未显示画面时不宣告复核。对照期间或手动锁定仍优先，不被后台结果覆盖。25ms 搜索步长不等于保证 25ms 实播精度。

每路原始压缩视频仍限制为 60 秒、96 MiB，按完整 GOP 淘汰，音频每段约 11 MiB；实际缓存时长受源码率和 GOP 长度限制。重连期间最多保留新旧两段，压缩视频合计不超过原有 96 MiB，PCM 最多约 22 MiB。1.2 中当前显示画面按主画面优先分配约 384 MiB 的共享图片预算，每路最多 24 张；隐藏后释放预取，停止时结束后台线程。普通播放最多使用早于目标 150ms 的已解码帧，不显示未来内容。`Decoder.diagnostics()` 提供源尺寸、帧率、收帧数、最近收帧率、视频时间戳空档、压缩缓存大小/时长和后台图片解码耗时；Canvas 统计不同帧显示次数及重复轮询次数。本地测试覆盖三路 1440P60、精校正计算期间的实际显示帧数、B 帧、30/59.94 帧、源像素一致性、跳转、停止与进程清理；不能据此保证任意网络和硬件的长期实播性能。

v0.1.28 将完整粗匹配的指纹距离与精校正的时间搜索也改为 NumPy 批量计算；已经确认的偏移先做附近跟踪，失败再重新做全局搜索。小漂移单轮最多修正 25ms，避免微小变化反复触发整个 GOP 回解；大偏移仍重新确认后一次定位。性能自检改为实际绘制窗口，在三路 1440P60 取流时持续执行完整 60 秒历史的粗匹配和精校正，并连续施加向后的跟踪修正，避免只测短片段精校正遗漏实际开销。主画面与对照的绘制开启平滑采样，修复缩小和高 DPI 时细线/文字的采样失真；保留的原始图像不改变。虎牙/斗鱼由副画面切换为主画面时，不能仅凭请求档位相同认定缓存预览为最高画质；没有最高模式或实际最高档确认时，重新申请最高画质流，已确认的最高流继续播放。

重新勾选自动对齐会清零手动偏移，避免旧手动量与自动时间差叠加；1.2.2 起保留对照面板的开关状态。自动模式只使用估计的比赛时间差；主动修改偏移重新进入手动控制。手动修改副画面偏移尚无共同缓存时，副画面等待所需内容，主画面按原播放进度继续；共同缓存足够后一次定位恢复锁定同步。1.2 中副路断流独立静音隔离，恢复后按保留的相对偏移加入；主画面缓存不足才共同等待。不能播放尚未收到的未来画面，等待不修改主画面的暂停开关。

原画面墙的布局与房间保留，二路期间隐藏，关闭模式后恢复；二路界面嵌入右侧观看区域，不弹出独立观看窗口。斗鱼二路每次启动重新申请流地址，避免复用画面墙已使用的单消费者地址；连续 8 秒未收到画面会结束当前解码并重新取流，B 站轮换候选线路，其他平台重新申请地址。网络读取也有 6 秒超时，避免一直停在加载。持续收帧但播放时钟已跑到缓存前面时，按各活跃房间缓存的共同可用范围回调播放时钟；画面、声音与弹幕共用该时钟，保持手动相对偏移，不重启正常取流。未手动锁定时，超过 3 秒未收新帧的房间不参与时钟回调；手动锁定时仍等待该路的共同缓存，不让其他路单独继续。过大延后导致缓存不足仍明确等待。各平台共用相同的 FFmpeg 图像/PCM 缓存、自动匹配、手动偏移、画质、暂停、全屏及录制控制。声音通过独立的 Qt 音频输出混合，避免多路叠加过载；设备更换时重建输出。FFmpeg 子进程按本体现有方式后台运行并加入退出清理 Job。

## 短暂停顿诊断

`schema=2` 增加真实播放的逐帧节奏统计：`received_cadence`、`decoded_cadence`、`submitted_cadence`、`painted_cadence` 对应接收、图片解码、主画面提交和实际Qt绘制；记录最近一秒的间隔分位数、最长间隔、超过25/50ms的间隔和跨过的源帧数，重复绘制同一帧单独计数。`clock_cadence` 记录播放目标的推进幅度；`surface` 记录可见/最小化/曝光状态、源/画布尺寸、屏幕刷新率、播放速度和轮询间隔。Qt绘制统计不等同于显卡完成扫描输出。人工测试时保持真实主画面可见，记录感觉不顺的时间，再对齐上述阶段；合成素材成绩不能替代实播结论。

二路播放期间自动写入宿主 `logs/match-playback.jsonl`，每秒一条播放快照；文件轮转为主文件及两份备份，每份上限约 2 MiB。停止播放时结束采样。设置环境变量 `DDM_MATCH_DIAGNOSTICS=0` 后启动可关闭诊断。

- `ui_stall`：50ms 界面心跳超过150ms未更新，记录主线程函数栈和当前播放阶段；每次停顿最多一份，每秒最多一份，每次播放最多120份栈。未出现该事件不能排除更短的停顿，或采样线程同样无法获得执行机会的阻塞。
- `playback`：记录取帧轮询间隔、最慢一轮各阶段耗时、主画面绘制耗时、鼠标事件数量/控件类型、音频供给距今时间，以及目标/已显示时间、压缩缓存范围、目标前方余量、RGB帧范围、解码耗时/阶段和解码器创建次数（含首次创建）。
- `frame_wait`：记录进入/退出显示帧等待的目标位置与时间，避免短于一秒的等待被周期快照漏掉。缓存范围在后台读取，锁忙时只标记busy，不等待解码线程。

先用录屏的本地时间对齐事件：有 `ui_stall` 时沿函数栈和耗时阶段定位界面阻塞；界面心跳正常、压缩缓存覆盖目标而RGB落后时检查图片解码/转换；目标超出压缩缓存时检查收流和播放位置。音频供给间隔日志仍在宿主日常日志中。日志只记录性能数字、控件类型及文件名/函数/行号，不保存账号、流地址或弹幕正文。离线回归能验证诊断捕获和非等待读取，实际卡顿原因仍以复现日志为准。

## 人工验收

源码版与 EXE 版应分别按以下步骤验收，安装位置和配置目录各自独立。不要把源码版验证当作 EXE 验证。

1. 点击关注栏底部「比赛二路」，将两个正在看同一比赛的 B 站关注卡片拖到右侧。应自动开始并收到两路声音和弹幕，无论原有粉丝牌属于谁，昵称前都只显示一份来源主播文字标记，不显示原牌或虚构等级；重复拖动不能添加重复房间。
2. 切换主画面，两路声音与弹幕继续。若其他路解说慢约 4–5 秒，在它那一行尝试 −4 至 −5 秒，观察对照区的比赛计时器与相对偏移；较快主画面会相应延后。关闭对照时不停止取流。逐路关闭声音、调音量、关闭弹幕，操作只作用于该房间。确认音量条数值实时更新，格子静音按钮与该主播的声音开关双向一致；画质切换显示缓冲动画，收到画面后消失。
3. 自动同步至少等待 10–20 秒；自动匹配持续观察完整画面。用计时器或共同事件检查进度，必要时框选同一计时器放大对照并手动微调。静止、重复或不明确画面仍不能作为已对齐依据。
4. 主画面选择按钮应紧邻各主播名字，自动对齐应在下方，各路操作应分组横向铺满面板并保持单行。弹幕应贯穿右侧全高，设置栏应仅位于左侧视频下方，能滚动查看更多房间，并可拖动分隔线调高度；点击「最小化」后整栏消失、左侧画面扩大、右侧弹幕高度不变，左侧底部「展开设置」恢复原高度和调节值。播放偏移从零点击「−」再点击「+」，应回到零；改到 +3 秒时，该路声音与弹幕一起延后，主画面选到该路时画面也延后。切换预设来源颜色，应只改变该路弹幕颜色。将两路分别选仅左、仅右，声音应分别来自耳机两侧。
5. 换成不同比赛、主播全屏聊天或静止画面，自动状态应报告匹配不足，不能凭相同启动时间报告同步成功。
6. 调整主窗口大小，二路界面应随右侧观看区域改变；按 F 应放大主画面，再按 F 或 Esc 恢复；名字编辑框中输入 f 不应全屏。左上角应只显示 LIVE 和当前主画面直播间标题。进入二路时原蓝色观看标记消失，二路取流主播出现粉框；点击「比赛二路」关闭，原画面墙房间、布局与标记应恢复。遇到断流、移除房间、立即开始/停止或退出程序，主程序应继续响应，插件 FFmpeg 与弹幕工作线程最终退出。系统换音频设备后仍可继续听声音。
7. 同次启动关闭再开启，应重新收到画面并能暂停/恢复、切换主画面和画质。重启整个程序再开启二路，参与列表应为空，第一张拖入卡片应成为主画面；禁用插件并重启，应无插件入口；删除插件并重启，应停止加载。

另需拖入虎牙、斗鱼、抖音的关注卡片，与 B 站组合切换主画面，逐路测试画质、音量/声道、弹幕、偏移和暂停。移除全部直播间应立即清空，重新拖入应自动播放。

离线检查覆盖负偏移 4.5 秒的真实 PCM 读取与同进度双路预览、计时器跨分辨率图像匹配、框选区域放大和已确认偏移保留、主画面行按钮、音量数值、双向静音、画质缓冲、F 键及文字编辑隔离、直播标题与无人数提示、粉框与旧标记恢复、多平台接口、弹幕线程生命周期、移除全部房间后的画面清理，以及同步算法、安装与界面、本地音视频解码、退出清理和默认音频设备静音输出。新增精校正检查覆盖采样相位、正负偏移、压缩噪声、静止/不同内容/重复画面拒绝、手动锁定、过期后台结果，以及实际视频改变分辨率/亮度/对比度/叠层后的对齐与 300ms 残余误差识别。独立实播短测可用 `dev/selfcheck_match_sync_live.py` 显式指定房间；仅接收数据，不发送弹幕或保存账号，`--saved-login` 只读斗鱼已记住的登录态。长期比赛同步效果仍需上述人工验收。

本次只更新源码和插件，不导出新的 EXE 包；EXE 检查使用已有程序的隔离副本。

新增检查：`dev/selfcheck_match_sync_playback.py` 覆盖六路对照、收起保留偏移、滚动来源公平与共同播放时钟恢复；`dev/selfcheck_match_sync_native.py` 检查 Windows 二路 Canvas 的透明弹幕、旧位置擦除与离屏清理。

开发检查入口：`dev/selfcheck_match_sync_chat.py`（枚举 144 种三路加入顺序、主画面与弹幕开关组合，并检查逐步加入、移除重加和画面弹幕开关）、`dev/selfcheck_match_sync_offsets.py`、`dev/selfcheck_match_sync.py --audio-device`、`dev/selfcheck_match_sync_media.py`、`dev/selfcheck_match_sync_exe.py --audio-device`。`--audio-device` 检查实际默认音频设备，只输出静音数据。

实际直播读取检查可显式运行 `dev/selfcheck_match_sync_live.py 房间号 房间号 --seconds 25`，沿用当前登录态，只读取视频、音频数据和弹幕计数，不播放声音、不发送弹幕、不改配置。
