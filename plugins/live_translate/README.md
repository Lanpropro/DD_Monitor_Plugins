# 实时翻译 v0.1

插件 ID：`live_translate`。商店 1.0 安装包为 `live_translate-1.0.zip`，也可从“设置 → 插件”导入。最低本体版本为 `0.7.3`，实际运行要求见下文。

首次启用且模型尚未准备时，选择“下载默认模型”即可准备 **Qwen3-ASR 1.7B INT8** 日语等多语识别模型、**Qwen3 1.7B Q8** 本地翻译模型，以及音乐检测和运行库。用户确认后开始下载，完成后自动填入路径。已有模型和自定义配置可以继续使用。API 翻译和仅原文模式也需要本地识别。

内嵌字幕需要宿主提供 `set_tile_caption()` / `clear_tile_caption()`。旧宿主没有该接口时自动回退独立字幕窗；进程内识别和进程归组不依赖宿主修改。

## 首批范围

- 从宿主 `stream.resolved` 事件获取所选直播间的流地址和请求头，后台 FFmpeg 只解码音轨，不采集系统混音。
- YouTube／Twitch 音轨沿用宿主的系统／环境代理解析及本机 HLS 转发；FFmpeg 直连回环地址，由转发层处理上游代理、TLS 和分片重试。停止传译时一并停止转发，不内置代理内核。
- 在功能中心或格子右键「实时翻译…」进入；使用类似画中画的缓存头像卡片多选正在播放的直播间，点击开始后分别在各格子显示字幕。右键入口会加入对应房间，停止后可重新选择；一个房间失败或被移除时不停止其他房间。
- 关注栏左侧功能轨可单独固定「实时翻译」图标，沿用宿主的功能中心固定操作；竖屏时使用顶部功能中心。
- 点击功能栏图标，在按钮旁展开宿主内的附着面板，再次点击、按 Esc、点击面板外部或右上角收起；这些操作均不停止传译。面板随宿主缩放和入口位置重新定位，不替换直播墙或改变格子布局，使用 native child 保持在视频表面上方；右键房间入口打开面板并选中该房间。
- 参考 [BewlyCat](https://github.com/keleus/BewlyCat) 的圆角浮层、胶囊导航与轻量卡片层级，仅参考视觉、不复制其代码或素材。面板分为“传译／字幕／模型”三页，传译页使用语言方向卡和双语预览。复用本体公开选择器、开关、数值步进和操作按钮，配合本插件的视觉模块，随浅深主题更新；中央内容滚动，状态与开始／停止固定在底部。模型路径、字幕细节和资源诊断可折叠；翻页／收起不改变参数或启动模型。
- 默认面板为 440×560，可拖动顶部／底部中央的短线调整高度，松开后保存；正常窗口最小高度 360，宿主更小时按可用空间夹紧，恢复窗口后还原首选高度。语言区不足 300 px 时改为纵向排列，表单按宽度换行、中央内容滚动，字体和操作按钮保持可读尺寸。语言卡使用中性底色，直播间、原声／字幕语言、音乐和路径选择采用图标与悬浮提示，停止按钮保留无障碍名称；常驻说明移到对应控件提示中，处理耗时归入“模型 → 资源与诊断”。
- 本地 CPU 识别默认使用 Qwen3-ASR 1.7B INT8，不再提供 ReazonSpeech。识别依赖在 `DD监控室CE.exe` 进程内加载，正常路径不再启动插件管理的 Python 子进程；推理在可停止的后台线程运行。FFmpeg 与本地 `llama-server.exe` 仍是独立子进程，但以宿主同名的临时启动镜像运行，任务管理器可将它们归入 `DD监控室CE` 组；FFmpeg 的同目录 DLL 依赖会一并准备。
- 原文与译文成组更新，等待本句翻译时保留上一组；失败时显示当前原文和面板原因。可选择插件管理的本地翻译、用户自备 API 或仅显示原文；API Key 使用当前 Windows 用户的 DPAPI 加密保存，明文不进入插件配置。
- 优先使用宿主提供的直播格字幕覆盖层，位于视频和弹幕之上；全屏显示，画中画隐藏。字幕有独立显示开关，可设置原文/译文组合、总行数、字体大小、黑色背景透明度和字幕框宽高；背景逐行贴合实际文字宽度。播放栏显示或隐藏时自动调整字幕安全区域。旧宿主没有覆盖层接口时回退到独立字幕窗。更换直播源（画质、线路或续签地址）时保留当前会话，自动替换 FFmpeg 输入和识别队列并接续传译；只有关闭字幕窗、点击停止、移除房间或关闭宿主时结束会话。收起设置、按 Esc 或关闭设置窗口继续传译，再次打开保留参数。
- 记录最多 300 条阶段耗时及资源样本，可以导出 JSONL；不记录字幕正文、流地址、请求头、API Key。
- 音轨启动、首批 PCM 和退出原因同时写入宿主日志。FFmpeg 错误最多暂存 8 KiB，仅导出白名单类别、退出码、耗时和音频字节数，不写出原始错误文本。

## 唱歌与音乐标识

音乐检测随传译自动开启，不再提供用户开关；旧设置中的关闭值会迁移。音频分类模型目录需要包含 `model.int8.onnx`、`class_labels_indices.csv`，缺少文件时开始前明确提示。显式准备脚本会下载约 111 MB 的官方 Zipformer small 音频分类包，只提取约 27 MB 的 INT8 模型和标签；固定本次官方 HTTPS 文件的 SHA256（该旧发布无上游摘要），不在导入／装载插件时下载。新版内置目录齐全时可自动填入；自备运行环境在“模型”页选择音乐模型目录。

检测复用识别线程的 PCM。主分类器每秒判断最近 4 秒，高置信器乐沿用连续确认。歌唱居首且证据较强时可在首窗进入；较弱的人声音乐信号需要其他歌唱、吟唱或摇篮曲标签佐证。已经确认清唱后，仍有旋律证据的弱窗口最多续过四次，当讲话明显占优时更快耗尽这个限额。这样可减少清唱中字幕反复切换。

连续三个主窗以吟唱或摇篮曲为首、讲话分较低时，额外检查最近 1 秒。长短窗口都支持吟唱才进入该分支。原已确认的音乐仅凭弱证据延长时，每 0.2 秒用最近 0.8 秒复核，讲话占优就放行这段音频。

音乐期间每 100 毫秒检查音量和频谱变化。音色突变时用最近 0.4 秒复核，低噪声停顿后重新起声时用最近 0.8 秒复核。确认变化后提前撤标并清空旧音乐窗口。实际清标时刻取决于当前声音和输入帧大小，同人从唱转说时仍可能遮住开头的讲话。

音乐期间清除原文／译文并显示单行 `🎵MUSIC🎵`，跳过识别与翻译；恢复讲话或静音时清除标识，重置 VAD 与翻译上下文。标识在原文、译文、两者三种显示模式均可见，并遵循字幕总开关。停止、换源和音频断续会重置检测，不新增取流或模型进程。

分类结果有误判可能，尤其是歌唱和讲话重叠时；4 秒窗口与连续确认意味着不会在唱歌开始时立即切换。已用用户选定的真实游戏+BGM录音、官方唱歌录音验证基本区分，仍需真实主播唱歌／恢复讲话人工验收。当前不能分离游戏角色配音与主播声音，游戏配音仍可能被识别成原文。

本批不延后音视频，也没有实现按播放器 PTS 对齐字幕；因此不能用于验收「2 秒目标、5 秒上限」。下一批以实播数据确定压缩缓存、源时间戳与播放桥接。无需为了试用而修改宿主播放器。

## 准备本地识别

普通用户可在首次准备窗口或“模型 → 模型准备”中选择保存位置，点击“下载默认模型”。窗口显示阶段和已下载大小，可取消；取消删除未完成的下载临时文件，保留完整缓存供重试复用，完成后自动填入识别、音乐检测、本地翻译与运行库路径。全新安装下载约 4.5 GB，建议预留 6 GB 空间。网络断开、校验失败或保存失败时显示原因类别，可选择位置重试。

图形准备流程直接为 Windows x64／CPython 3.12 宿主安装固定版本的 NumPy 2.5.4、sherpa-onnx 1.13.8 和 sherpa-onnx-core 1.13.8 运行库，不要求用户另外安装 Python。PyPI wheel、模型及运行程序均检查固定 SHA-256；运行库放在所选目录的 `runtime/Lib/site-packages`，不会修改系统 Python。已有模型可选择“使用已有模型”，在模型页设置其路径。关闭或卸载插件会请求取消准备，后台任务退出前保留其所有者，不在主线程等待网络。

宿主需包含功能中心及 `context.recording.options()` 接口。最低版本号只是初筛，请使用配套根目录 `run.cmd` 验收。正常插件路径要求宿主为 CPython 3.12；模型准备会提供 NumPy 与 sherpa-onnx，不需要另行启动 Python 进程。

用已安装的 Python 3.12，在插件源码仓库运行：

```powershell
python plugins/live_translate/prepare_runtime.py --directory work/live-translate-runtime
```

脚本在指定目录建立独立运行环境、安装 NumPy 和 sherpa-onnx，然后准备约 2.4 GB 的 Qwen3-ASR 1.7B INT8、Silero VAD、音乐分类模型、约 25 MB 的 llama.cpp Windows x64 CPU 运行程序和约 1.83 GB 的 Qwen3 1.7B Q8 翻译模型。各下载文件按固定 SHA-256 校验。只准备识别时可加 `--recognition-only`。准备完成后，本地识别与翻译可断网使用，无需 API Key。安装标准 ZIP 后，脚本位于 `plugins_user/live_translate/prepare_runtime.py`。

“运行库目录”选择含 `Lib/site-packages` 的运行库目录；旧配置中的 Python 路径（例如 `runtime/Scripts/python.exe`）仍兼容，也可直接粘贴。“识别目录”选择 `model_dir`；本地翻译在名称下拉框选择 GGUF，运行程序位于下方路径折叠区。手动选择运行库路径只用于定位 `site-packages`，不会执行外部 Python 或自动安装依赖。

Qwen3-ASR 模型目录应包含：

```text
conv_frontend.onnx
encoder.int8.onnx
decoder.int8.onnx
silero_vad.onnx
tokenizer/vocab.json
tokenizer/merges.txt
tokenizer/tokenizer_config.json
```

已有模型可在“模型目录”直接选择上述完整目录，无需复制进插件。仅支持 sherpa-onnx 兼容的 ONNX 导出，普通 `safetensors` 或 GGUF 不能用于识别。下拉框会区分“模型未就绪”和“模型已就绪”（文件齐全），选择目录不加载权重；开始前仍会校验并列出缺失文件。旧 Reazon 配置会改为 Qwen 引擎，使用完整的内置 Qwen 路径；没有内置模型时清空旧目录，等待用户选择。不会自动删除用户自备目录或下载模型。参见 [sherpa-onnx 模型说明](https://k2-fsa.github.io/sherpa/onnx/qwen3-asr/pretrained.html)。用户选择的原声语言作为每个识别流的 `language` 提示，同时用于翻译提示词；优先按所选语言识别，不按字符删除夹杂的人名或术语。接口没有可配置的语言百分比权重，仍可能误识别。原声语言与字幕语言在运行时锁定，停止后修改。

## 翻译与千问

普通 Qwen 文本模型与 Qwen3-ASR 是不同模型，分别负责译文与听写。两者不能互相替代。

本地翻译模型的名称选择同时显示在首页及模型页，路径编辑放在折叠区。API 模式优先恢复上次填写／使用的接口与模型，未记录时留空并显示输入提示，不预填 `qwen3:0.6b`。旧的实际 API 配置保留；没有接口地址的旧本地默认值会清空。本地服务内部的 `live-translate` 别名不覆盖 `api_profile`；API Key 仍单独加密保存。编辑 API 字段后离开焦点、收起面板或卸载时保存配置，不要求先开始传译。

“模型 → 翻译提示词”可分别编辑本地和 API 模板，使用 `{source_language}`、`{target_language}` 引用所选语言，其他大括号按原文字面保留。留默认或点击“恢复默认”沿用原模板；本地最多 400 字、API 最多 2000 字，运行中禁用编辑，下一次开始生效。自定义提示词仍附加仅输出目标译文的约束，并经过正文清理、目标文字校验和原有的有限重试；不能通过提示词关闭这些检查。修改提示词不保证提高准确率，本地小模型尤其可能受过长提示影响。

- **本地翻译**：默认选项。填写准备脚本输出的 `local_model` 和 `local_server`（开发版已预填）。开始传译时自动启动并加载模型，停止传译或关闭字幕窗后结束进程、释放权重。不需要自行启动服务，也不需要填写地址、API Key。
- **API 翻译**：显示接口地址、模型名称和 API Key。Key 通过当前 Windows 用户的 DPAPI 加密后保存在插件设置中，重新打开面板或宿主后自动解密填入；清空输入框并离开焦点可删除保存值。可填写在线兼容接口，或已有本地 Ollama / llama.cpp 服务的 `/v1` 基地址及其实际模型标识。这个模式不启动插件的本地翻译进程，且只发送识别文字。
- **仅显示识别原文**：不启动翻译模型、不发翻译请求，保留原文字幕用途。
- API 失败、达到等待上限或前一个请求仍未结束时，当前句保留原文，不堆积翻译任务。已超时请求的迟到结果不覆盖新字幕。翻译方式在运行期间锁定，停止后可切换，避免界面选项与实际运行服务不一致。

本地翻译默认使用官方 Qwen3 1.7B Q8 GGUF，由 llama.cpp `b12211` 在 CPU 上运行。沿用 2 线程、1024 token 上下文、单推理槽和关闭思考输出的默认设置。

本地翻译保留最多两条适用的短前文、与当前句匹配的房间术语，以及原等待预算内的有限复核。停止、换源或音频丢弃后清空上下文。结果校验会拦截明显复述原文、提示语和不符合目标语言的译文。仍可能出现错译、漏译和中日混写。校验通过只代表满足输出规则。

识别出新句子后，保留上一组字幕，等当前翻译完成或达到等待上限，再同时更新原文与译文，避免等待期间反复清空中文。音乐标识与清除不等待翻译；仅原文模式不等待翻译请求。译文失败时仍保留当前原文和面板原因；资源导出包含 `has_translation`，不包含字幕正文。

## 资源与延迟边界

模型仅在开始后加载。同一配置的多个房间共享一份 ASR 模型，并串行访问原生解码器；各房间拥有独立识别线程、VAD、音乐窗口、上下文、音轨进程与有界输入队列。本地翻译共用一个服务进程，API 模式不启动它。最后一间停止后释放共享识别权重，停止全部后清理翻译进程和启动镜像。设置窗口收起不停止字幕任务。每个本地大模型默认 CPU 两线程，可在 1～8 线程调整，本地翻译固定不使用 GPU。

多选会增加音轨带宽、VAD／音乐分类开销和识别等待，API 请求量也随语音增加；共享权重不代表计算成本不变。CPU 跟不上时按每房间容量上限丢弃积压音频、重置不连续状态；不无限堆积或将一个房间的译文交给另一房间。语言和模型参数当前对所选房间共用，未做声源分离或自动质量提升。

停止会立即清除字幕、停止取流和翻译服务，并请求识别线程退出。正在进行的原生识别调用会在返回后释放模型，GUI 不阻塞等待；其 QObject 由退役定时器暂时持有，避免卸载设置窗／会话时销毁活动线程的信号对象。上一轮识别尚未退出时拒绝再次启动，提示稍后重试，不并行加载第二份识别模型。

PCM 为 16 kHz 单声道 s16le。单个消息最多一秒，Qt 待发队列最多约两秒；超载时丢弃输入，下一次有效输入重置 VAD，避免拼接不连续音频。操作系统管道和 FFmpeg 还有自己的少量缓冲，因此该值不是整个链路的延迟上限。VAD 停顿参数为 500 ms、最大语音参数为 4 秒，VAD 保留窗口为 10 秒；实际段长取决于 VAD，4 秒不是精确切断或字幕延迟上限。这是对用户明确指定的真实直播录音做短段／较完整段对照后的参数选择，可能增加等待时间，仍须人工验收。

每个房间最多一个翻译请求在途；本地服务只有一个推理槽位，房间越多越可能达到等待上限。超时后继续识别，该房间的旧请求结束前不再提交新翻译。资源记录中的 `asr_ms` / `translation_ms` 是完成分段后的处理耗时，不包含采集、排队、断句与播放，不能当作端到端延迟。资源事件汇总活动房间，音轨／字幕事件带房间 ID，均不包含字幕正文或凭据。

`child_rss_bytes` 只合计全部活动取流进程和一份插件管理的本地翻译服务 RSS；识别模型、各房间的音乐分类器与推理分配在宿主进程内，必须结合宿主 RSS 与 `recognition_embedded` 样本阅读，不能把该字段当作完整内存。API 模式下调用的外部服务、宿主 Qt / 播放器增量同样必须另行采集。后台任务和字幕历史均有容量上限；尚未设置未经测量的硬性内存预算。下载文件大小不代表运行内存。

## 字幕覆盖层

新宿主通过 `context.set_tile_caption()` / `clear_tile_caption()` 提供字幕覆盖层。插件只在当前会话绑定的格子上提交文本，不把字幕加入弹幕列表，也不改变弹幕轨道：

- `enabled`：独立显示总开关；关闭清除所有房间的插件字幕，不停止识别和翻译，旧的单房间偏好不能覆盖总开关。弹幕开关不恢复已清除的插件字幕；直播视频里烧录的字幕和平台弹幕不受本插件开关控制。
- `mode`：`both`、`original`、`translation`。
- `lines`：总行数预算 1–4；默认原文和译文各占一行，更多行数用于换行。
- `opacity`：黑色圆角背景不透明度 0–100。
- `font_size`：字体像素大小 10–64；过大时宿主会按当前字幕框高度安全截断，避免文字被裁切。
- `width` / `height`：相对视频宽度和可用高度的百分比；播放栏出现时可用高度会缩短。
- `x` / `y`：0–100，在字幕框剩余可移动空间中的相对位置；默认居中靠下。
- `locked`：锁定后鼠标穿透；解锁后可拖动字幕、拖动右下角缩放、双击复位。右键字幕有显示组合、字号、锁定和复位；锁定后通过格子右键“解锁翻译字幕”或设置页解除。

最新本体的“字幕”页在参数滚动区上方固定显示可操作预览，拖动／缩放与参数双向同步；采用与真实字幕相同的渲染和手势。默认样式修改只覆盖被修改的字段，各房间在格子上的独立位置、锁定和快捷设置通过 `caption_rooms` 保存。旧宿主没有预览／编辑回调接口时仍能显示静态字幕，不具备本次原生交互能力。

字幕覆盖层由宿主管理，使用宿主内置思源字体绘制中日文，不依赖系统字体回退或 `VideoDanmaku` 的私有绘制状态。黑色背景按每一行的实际文字宽度实时绘制，不再覆盖整个字幕框。旧宿主返回不可用时不报错，继续使用独立 `Captions` 窗口。

首页的“识别”和“翻译”下拉入口列出当前模型同级目录及插件 `vendor/models` 中的兼容候选，可通过“选择其他模型”导入别处的路径；不递归、不扫描整盘、不下载或列出尚未安装的模型。识别需符合支持的 Qwen3-ASR ONNX 完整文件结构，翻译候选检查 GGUF 文件头，是否被当前 llama.cpp 支持仍需实际加载确认。路径与模型页共用同一设置。运行环境仍在模型页配置，传译过程中模型入口禁用，停止后可更换。API 模式首页可直接填写模型名称。

清唱出现标识的时间取决于此前 4 秒的音乐与讲话证据。清唱中间若出现讲话证据，标识可能短暂清除，随后重新出现。

## 人工验收

1. 从插件商店安装，或将 `live_translate-1.0.zip` 导入宿主插件页，启用并从宿主根 `run.cmd` 重启。首次启用时确认下载默认模型。
2. 播放一间日语或英语直播，右键选择「实时翻译…」。选择「本地翻译」，确认识别及本地翻译的路径已就绪，不填写 API Key。
3. 连续点击左侧图标，附着面板应展开、收起、再次展开，直播墙和格子布局保持；按 Esc、点外部或切换其他功能时收起。横竖窗口缩放时面板留在宿主边界内，下拉选项和文件选择不误收起。修改参数／页签后重新展开应保留；从另一房间右键打开时选中对应房间。
4. 开始后原文与本地生成的译文应成组更新；等待下一句翻译时保留上一组。失败时只显示当前原文，面板提示原因；资源统计能区分宿主内识别线程与 FFmpeg/本地翻译子进程。收起设置、按 Esc 或关闭设置窗口，字幕应继续；关闭字幕窗后，识别线程、本地翻译及 FFmpeg 应结束。本地模型准备完后可断网复测。
5. 停止后切换「API 翻译」，应显示地址／模型／API Key。填写自行准备的接口重新开始，应正常生成译文且不启动插件本地翻译进程；重启宿主后 Key 应仍在密码框中，配置文件只出现密文字段。断网或接口变慢时原文应继续，翻译不无限排队。选择「仅显示识别原文」时不产生翻译请求。
6. 选择两间直播并开始，应各自在对应格子输出；停止一间、换源或移除一格不影响另一格，不出现串字幕。音乐检测自动运行；真实唱歌仍需分别验收。
7. 在字幕页拖动预览、缩放右下角，参数同步；滚动下方参数时预览不移走。在真实格子拖动字幕、改变大小、锁定后点击视频应穿透；通过格子右键解锁，切换显示组合／字号，缩放或全屏后保持相对位置。原生 Windows 视频层级与系统缩放须实机确认。
8. 浅深主题下卡片应为纯色；反复打开识别模型下拉和翻译模型展开项，面板位置与内容宽度保持稳定。
6. 切换画质或直播源后，传译应自动接续，不应退回停止状态，也不应重新加载本地翻译模型；切房、停止播放、移除格子、关闭宿主时字幕不再更新且进程结束。
7. 对同一批真实直播分别记录识别及译文错误、处理耗时、超载丢弃、宿主和子进程内存。持续运行至少 30 分钟，导出记录。2 秒／5 秒端到端验收待下一批同步播放实现后进行。

自动替身检查、真实嵌入线程样本和官方语音样本只验证功能回归，不证明真实直播的精度、延迟或性能改善。原投稿记录的进程分组、字幕覆盖层、换源续传和 API Key 人工结果属于作者自述，当前维护者独立验收尚未完成；2 秒／5 秒端到端延迟和连续 30 分钟资源趋势仍需后续实测。

完整录音回归入口为 `tests/check_live_translate_pipeline.py`，通过本机 HTTP 录音样本运行真实 FFmpeg、本地识别和本地翻译，并核对子进程总内存统计及停止回收。`--rooms 2` 验证两路分别产出译文、共享模型／服务和最后使用者回收；默认仍可验证单路。需要显式指定样本、模型、运行环境及 FFmpeg 路径；这个回归入口不读取真实账号，不用作实播性能证据。

## 模块职责与来源

| 模块 | 职责 |
| --- | --- |
| `plugin.py` | 宿主入口、单一流快照来源、切房与卸载协调 |

| `anchored_panel.py` | 宿主拥有的 native child 浮层、功能栏锚点定位、边界适配、外部点击／Esc 收起及事件过滤器生命周期 |
| `panel_visuals.py` | 语言方向卡及随宽度协商的布局、双语预览、控件图标与中性主题绘制，不拥有传译任务状态 |
| `panel_controls.py` / `source_picker.py` | 固定提示宽度的下拉框、保留原按钮信号的圆角状态绘制、缓存头像房间多选；不读取宿主私有状态、不启动网络请求 |
| `model_picker.py` | 首页现有模型路径选择，直接更新模型页编辑器；不拥有模型或下载任务 |
| `model_catalog.py` | 只发现选定目录附近及内置目录的完整 ONNX／GGUF 候选，不加载模型或扫描整盘 |
| `setup_dialog.py` | 首次启用询问、确认后的后台准备、进度／取消及任务退出前的所有权；不在构造时下载 |
| `runtime_setup.py` | 固定摘要的 Windows 运行库安装与既有模型准备协议，无系统 Python 安装依赖 |
| `session_settings.py` | 模型设置持久化、独立的上次 API 选择及旧默认值迁移；不存 API Key，不将房间术语写入全局模型设置 |
| `glossary.py` / `glossary_editor.py` | 与字幕摆放共用房间键，按房间／目标语言校验、编辑与保存明确术语；只向当前句提供匹配词条，不读取账号或推断主播词库 |
| `prompt_policy.py` | 本地／API 默认模板、用户模板变量替换、有限原文背景与输出约束 |
| `session.py` | GUI 线程中的 FFmpeg QProcess、宿主 HTTP 中继生命周期、启动／退出诊断、识别线程控制面、容量控制、迟到结果过滤、停止回收 |
| `session_group.py` | 多房间会话协调、单翻译服务、独立失败和汇总资源；复用单房间 Session |
| `caption_presenter.py` | 按房间路由字幕、独立摆放偏好与旧宿主字幕窗；不拥有推理模型 |
| `recognizer_pool.py` | 按识别配置引用计数共享原生模型、解码互斥、最后使用者释放 |
| `audio_diagnostics.py` | 有界 FFmpeg 错误分类，不导出原始 stderr、地址或请求头 |
| `options.py` / `protocol.py` | 模型与参数校验、FFmpeg 参数、PCM 消息边界 |
| `recognition.py` | 本地识别及 VAD；在识别线程就绪后加载权重依赖 |
| `speech_segments.py` | 有界 VAD 音频续接、草稿频率、短句等待、停顿优先强制切分与尾部保留；不拥有模型 |
| `speech_pipeline.py` | 识别线程内执行草稿／定稿、复用相同音频识别结果，仅定稿进入翻译与原文上下文 |
| `quality_policy.py` | 空结果、长音频短文本、异常重复等疑似失败信号；不维护讲话黑名单，不替代人工语义判断 |
| `caption_progress.py` | 每个 Session 独立的草稿／定稿顺序和上一条译文；切源、停止和音乐切换时清空 |
| `translation.py` | 文字翻译协议、等待截止、单请求调度与各房间独立的最近两条定稿原文；换源重置，关闭清空 |
| `local_translation.py` | 本地 CPU 翻译服务进程、就绪检测及停止；多房间时由 SessionGroup 统一拥有和计入资源 |
| `embedded_recognition.py` | 宿主进程内的识别线程，有界输入队列和模型生命周期 |
| `host_process.py` | 为 FFmpeg/本地翻译创建宿主同名临时启动镜像并清理 |
| `caption_style.py` | 字幕显示组合、行数、透明度、框宽高和持久化映射 |
| `text_policy.py` | 语言名称、说明标签清理、背景回抄和目标文字校验；不加载模型、不替代语义评估 |
| `music_detection.py` | 同音轨的本地音频事件分类、有限窗口和讲话优先状态切换 |
| `secret_store.py` | 使用 Windows DPAPI 加密和解密 API Key；不写入明文 |
| `worker.py` | 兼容/诊断用独立推理入口；正常插件不启动 |
| `prepare_runtime.py` | 显式准备识别环境、识别和翻译模型、CPU 推理程序；不在插件装载时下载 |
