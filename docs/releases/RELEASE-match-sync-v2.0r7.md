# 比赛二路同步 v2.0r7

发布日期：2026-11-02（本地构建，待维护者实测后决定是否发布 Release）

## 为什么又改一版

`2.0r6` 加的日志把断点指出来了：点击回调确实触发、播放行也找到了，但**只取到 1 帧**（偶尔 2 帧）。检测器拿到单帧时无法把「主播的脸」和「游戏画面里的脸」分开，于是返回「没有候选」——界面上就是点了没反应。

## 本次改了什么

- **取帧改为多点采样**：点击后先抓画中画当前显示的那一帧，再每隔 140 毫秒抓一次，共四帧（约 0.42 秒）后送检测；解码器历史能补到帧时一并补上。只有一帧时不再送检测，改为提示「等画面稳定后再点一次」。
- **人脸聚类放宽**：相邻帧之间同一张脸的框会抖动/放大，实测两帧的重叠只有 0.27，旧阈值 0.30 会把主播拆成两个「单帧簇」而被丢弃。现在「重叠 ≥0.20」或「中心距 ≤0.75 倍脸框且尺寸比 0.5–2.0」都算同一张脸。
- **只认持续出现的簇**：只有出现帧数最多的那批人脸参与打分，游戏里一闪而过的脸不再抢位置。
- **不再假定摄像头是 16:9**：实机右上角那块约 142×146（近正方形），旧先验把框横向撑到 248 宽。现在按 `1.0 / 1.3 / 16:9` 三种形状出候选再打分。
- **静止度加分**：摄像头窗口在相邻帧里几乎不动，游戏画面一直在动；候选框内部帧间差明显低于全画面时加最多 3.0 分，压掉「游戏里的脸碰巧被框住」的候选。

## 验证

- 用维护者实机导出的四帧复原：两帧时 `(0.734, 0.028, 0.230, 0.270)`、三帧时 `(0.821, 0.026, 0.143, 0.276)`，都套住右上角摄像头；`game only`、`empty`、`single frame`、`faces off` 四个 guard 仍然全部返回 `None`。
- 合成标定集 8/8 出框。

## 兼容性

- 宿主：DD 监控室 CE 0.6；Python 3.11 / PySide6 6.11；`opencv-python` 可选。
- 配置无需迁移，`2.0r6` 的设置可直接沿用。

## 安装

1. 下载 `match_sync-2.0r7.zip`（GitHub 自动生成的 Source code ZIP 不能当安装包）；
2. 在 DD 监控室 CE 的插件页导入该 ZIP；
3. 插件列表里版本应显示 `2.0r7`。

## 如果仍然不生效

日志仍在（`自动框选：` 前缀）。搜一行 `取到 N 帧`：若是 1 帧，说明那一刻画中画没在刷新；若是 4 帧但「没有候选」，把 `%TEMP%\match_sync_autocrop` 里的帧留下即可复算。
