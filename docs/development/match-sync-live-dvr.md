# 十分钟整组回看：现成方案与当前实现

2026-10-25。目标是最多十分钟的可拖动时间轴，回看时仍接收直播并在直播进度上
自动对齐。直播采集/匹配与用户观看进度必须独立，声音、画面和弹幕共用观看进度。

## 传统平台及现成组件

| 方案 | 已核实能力 | 对本插件的适用性 |
| --- | --- | --- |
| 平台 DVR | YouTube 官方支持直播暂停、回退和继续播放，取决于主播的 DVR 设置 | 不把第三方平台提供历史分片当作必备条件；本地只能回看本次已收到的内容 |
| HLS 滚动窗口 | RFC 8216 定义直播列表可按顺序移除旧片段；FFmpeg 提供 `hls_time`、`hls_list_size`、`delete_segments` | 可作为通用本地 DVR，采集端写新片段、观看端读旧片段，并淘汰过期片段 |
| mpv 磁盘缓存 | 已有 seekable cache、前后缓存预算和 `cache-on-disk` | 官方手册指出磁盘文件只追加，淘汰后不复用文件空间，关闭媒体才删除；不能仅设置 600 秒就认定磁盘是十分钟环形缓存 |
| 本体 FFmpeg 分片 | `ddm/recording.py` 已有十秒分片、缓存裁剪和导出 | 优先参考其参数/清理规则；当前接口偏向录制及保存回放文件，不能直接当作插件连续回看与多路对齐接口 |

官方来源：[YouTube DVR](https://support.google.com/youtube/answer/9296823?hl=en)、
[HLS RFC 8216](https://www.rfc-editor.org/rfc/rfc8216.html)、
[FFmpeg HLS](https://www.ffmpeg.org/ffmpeg-formats.html#hls-2)、
[mpv 缓存选项](https://mpv.io/manual/stable/#cache)。

## FFmpeg HLS 离线验证

本机脚本位于 CE 工作区的 `work/test-artifacts/match-sync/replay-ten-minutes/hls_dvr_probe.py`。
使用 12 分钟合成 H264 内容以 100 倍内容速度输入，视频复制、声音 AAC，片段目标
2 秒、播放列表 300 条，启用旧分片删除和临时文件原子发布。验证结果：

- FFmpeg 仍运行时，成功解码已完成的历史分片。
- 播放列表序号由 0 推进到 60，最终 300 条、合计 600 秒。
- 磁盘保留 302 个分片（含删除宽限），最旧/最新保留片段均可解码。

这是组件可行性实验，尚未接入正式插件，不代表十二分钟墙钟长测或多路/真实直播
已验收。HLS 的目标片段时长不等于任意流都严格两秒切片，复制视频时受关键帧限制。
生产接入还需解决未完成分片、音视频时间映射、断流 discontinuity，以及旧分片被
淘汰时仍有读者持有的情况，不能把实验命令直接当作完整功能。

## 本轮已实现的插件适配

当前继续复用现有 FFmpeg → PyAV 采集、压缩包缓存、PictureReader 与声音混音。
缓存改为按关键帧组保存临时磁盘文件，PCM 使用固定容量磁盘映射环；不是 HLS
封装，也未引入第二套播放器或重复取流。视频按时间/2GiB 每路预算淘汰，匹配特征
仍保留最近 60 秒。时间轴限制在 600 秒以内，实际范围取已收到的共同历史。

直播时钟、自动匹配和缓冲控制使用直播位置；画面、PCM 与弹幕输出另外减去回看
秒数。回看期间分析不读取旧画面 canvas 的时间，自动匹配不停止。每路弹幕历史
最多 20000 条，极高负载下可能短于媒体历史；磁盘失败退回 60 秒内存缓存并提示。
源时间戳重置/断流、超出磁盘限额或刚启动时，可回看范围可能不足十分钟。

后续若统一本体与插件缓存，优先验证 FFmpeg 标准分片/滚动清单的复用，保持
本轮已验证的直播与观看双进度、声音和弹幕映射，不直接更换播放/对齐核心。
