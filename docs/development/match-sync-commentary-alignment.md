## 现有实现与结论

`Viewer.analyse` 比较 `History.snapshots/details` 中的连续画面特征；
`History.audio` 已保存 48kHz 双声道 PCM，但当前匹配没有使用声音特征。
没有比赛画面时，应保留原匹配的拒绝条件，不能降低置信门槛强行应用偏移。

| 可用信号 | 可行路径 | 接入前必须验证 |
| --- | --- | --- |
| 相同游戏音效或官台声音 | 从现有 PCM 缓存提取共同声音，搜索时间差；作为独立匹配来源 | 解说覆盖、压缩/降噪、响度、重放插入、持续静音、重复音乐及速度漂移 |
| 正常递增比赛计时器 | 人工选择计时器区域，OCR 连续读取数值与对应帧时间，建立比赛时间映射 | 秒数跳动、暂停、回合/局重置、误读、画面缩放，以及低频后台识别的性能 |
| 只有比分数字 | 可辅助判断同一场比赛，不能唯一定位播放时间 | 比分长时间不变，不可单独当作偏移证据 |
| 仅独立说话且没有共同计时器 | 当前无可靠的自动时间锚点；用独立播放与人工偏移 | 不能把主播说出事件的反应时间当作固定延迟 |

声音优先调查，因为已有 PCM，无需新增 OCR 运行依赖。OCR 保持调查状态：既有
合成计时器记录为 9/12 命中，不能当作足够准确的自动匹配。本轮没有启用 OCR。
Windows OCR 是否能创建指定语言引擎取决于设备可用语言，创建也可能返回空值。
参见 [微软接口文档](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine.trycreatefromlanguage)。

## 本轮离线声音探针

`tools/probe_match_sync_audio.py` 对两份同时采集的 16-bit PCM WAV 做低频采样与
归一化互相关，只输出候选偏移。正数表示相同声音在副路文件中出现得更晚。
WAV 的采集起点必须已知，否则文件起点差会混入输出偏移。探针不连接直播、不调整
播放器、不替代生产匹配。互相关方法本身可参见
[FFmpeg axcorrelate](https://www.ffmpeg.org/ffmpeg-filters.html#axcorrelate)。

```powershell
python tools/probe_match_sync_audio.py --main main.wav --secondary secondary.wav --output work/test-artifacts/audio-probe.json
python tests/check_match_sync_audio_probe.py
```

合成测试验证：共同信号在增益变化及独立噪声下能找回 +3.27 秒，反向输入找回
-3.27 秒；无关音频、共同信号被噪声淹没、静音及周期单音被拒绝。这仅验证数学
路径与拒绝条件，随机信号不是实际游戏音效或人声，不据此宣称已解决纯解说对齐。
当前阈值是探针参数，尚不能直接移入正式自动匹配。

## 历史后续建议（已被上述决定取消）

先用经授权的本地比赛片段与解说片段做成对测试，人工标注共同事件与实际时间差；
保留收听中的原始混音，包含解说压住游戏声、音乐及无共同声的反例。统计误接受、
误差、首次获得候选时间及持续漂移。要求多个不重叠片段的候选一致；模糊时拒绝，
保留人工确认和独立播放。可用计时器时，用其粗偏移交叉核对声音候选。

计时器方案应比较 `帧时间 - 比赛秒数` 的差值，并用多帧验证正常计时；暂停、
重置及识别缺口必须使候选失效。只读到整数秒时精度有限，不能直接冒充现有
约 0.2 秒精校正。只有取得真实素材证据后再决定是否加入运行时声音匹配/OCR。
