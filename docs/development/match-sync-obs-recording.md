# 分音轨录制：OBS 方案参考

2026-10-25。用户要求参考 OBS 的方案；本轮只研究方案，不改动已实现的音轨布局。

OBS 的官方多音轨指南把每个声音源分别分配到独立轨，并建议同时把所有声音送到
第 1 轨，以便普通播放器直接听到完整声音；其他轨用于后期分别处理。官方高级录制
指南建议使用 MKV，可在录制后转封装成 MP4。

来源：[多音轨录制指南](https://obsproject.com/kb/multiple-audio-track-recording-guide)、
[高级录制指南](https://obsproject.com/uk/wiki/advanced-recording-guide-with-multi-track-audio)。

## 对本插件的建议

| 项目 | 当前实现 | 建议采用的方式 |
| --- | --- | --- |
| 音轨布局 | 主路及每个副路各一条，源标签具名 | 保留独立轨；可额外增加第 1 条完整混音轨，兼顾直接播放与剪辑 |
| 时间基准 | 视频原始包与缓存 PCM 使用主画面内容时间 | 保持共同内容时钟，不能让每个声音源各自从零开始写文件 |
| 收听与录制 | 收听音量/静音/左右输出不改写独立轨 | 独立轨继续保留原始声音；完整混音轨可另行确定是否遵循收听混音 |
| 容器 | MKV + 视频复制 + 每路 AAC | 保留 MKV；录后转封装 MP4 可独立评估，不重新编码视频 |
| 依赖 | 插件复用现有 PyAV 和缓存 | 借鉴 OBS 的源与轨道分配方式，无需安装或运行 OBS，也不引入桌面采集 |

增加完整混音轨前需要确定默认布局、混音轨的音量语义，以及缺失/新加入声音源的
行为。当前用户明确需求仍是每路声音独立，下一次讨论后再决定是否额外增加混音轨。
本轮不预先加入轨道矩阵、任意路由或外部 OBS 控制。

后续验收需验证：普通播放器能否听到完整混音、剪辑软件能否分别导入具名轨道、
两路声音互不串轨、音视频时间一致、停止/异常中断可恢复、长录制分段及转封装。
