### 独立插件补齐1440p60连续播放（2026-11-17，待界面人工验收）

- 对应[本体Issue #235](https://github.com/Lanpropro/DD_Monitor_CE/issues/235)。高画质实现仅加入`youtube_live`；`global_live`、Twitch、CHZZK的协议与行为不变。宿主只增加通用的私有媒体读取器交付接口。
- 按实际直播格式生成画质档位，支持VP9高画质+AAC音频；连续读取同一直播序号的分片，由宿主FFmpeg只复用为Matroska，不转码。1080p及以下优先H.264；自动从最低档开始，预览优先沿用HLS；切档、取消、停止和卸载回收独立读取器。
- 固定yt-dlp 2026.10.26、Node24.11.0与bgutil2.0.2来源校验组件。前两项首次自动下载并校验SHA256；bgutil及其锁定依赖随独立插件内置，许可证和源码保留。无需用户手动部署服务、导入Cookie或提供Token；第三方解析输出和媒体签名不进入错误提示。
- 实际证据：用户指定的`dklfSqHUu4c`在现有代理下返回308视频和140音频；连续约50秒读取/复用，ffprobe确认2560×1440、60fps、VP9、AAC，10秒双轨解码检查无报错。网络也出现过TLS关闭/超时和来源校验失败，不能将一次成功视为所有节点均稳定。
- 自动检查：画质选择、真实generator协议、缺音轨、非法来源、序号与部分读取、过期地址、停止、组件完整性及独立插件边界通过；宿主本机HTTP交付、消费者隔离、取消/卸载和播放器交接检查通过。声音听感、界面手选/自动来回切档和长时间播放待维护者从根`run.cmd`验收。
- 集成：追加原[PR #67](https://github.com/Lanpropro/DD_Monitor_Plugins/pull/67)，依赖配套宿主接口；开发候选未发布，不关闭Issue235。下方“尚未实现”保留为此前调查时点，不能用于描述本候选的新状态。
- 起播进一步以音视频共同可用的直播头序号为准，避免音轨发布稍慢时请求未来分片；未来404按片长有限等待。新增两项回归后专项16/16通过。已安装候选的端到端重试仍出现分片读取失败、另一次在元数据阶段连接失败，不能据50秒独立媒体验证宣称当前节点的全链路稳定；界面人工验收继续待办。

### 1440p60 直播实况核验（2026-11-17，尚未实现）

- 来源：[本体 Issue #235](https://github.com/Lanpropro/DD_Monitor_CE/issues/235)，以及维护者提供的公开直播 `dklfSqHUu4c`。维护者官网统计截图确认2560×1440@60、VP9（itag 308）与AAC（itag 140）；匿名公开页面也返回对应两路自适应格式，当前取得的响应没有HLS/DASH清单。
- 当前缺口：插件只接受H.264 HLS；Streamlink 8.6.1的YouTube直播路径不返回这些自适应格式。只移除编码筛选无法补齐分离音视频、直播分片与请求授权。
- 实际探测：公开页面中的308和140媒体地址直接请求均返回HTTP403。核验固定版本yt-dlp 2026.10.26后，普通提取遇到登录/客户端验证提示，Android VR客户端明确缺少GVS PO Token，Safari/iOS测试未成功取得格式，公开嵌入客户端对这场视频返回不可用（152-18）。网络超时/TLS失败与403并存，尚未确认403的唯一根因；这些结果不证明所有YouTube频道都需要登录。
- 结果：尚无可验收的2K连续播放修复，本轮没有改播放协议、清单版本或代理设置。后续仍需实现并真实验证高画质来源校验、连续分片、VP9视频与AAC音频同步、切档/停止清理；不能以菜单出现1440p或合成测试代替实播通过。
- 状态：原[PR #67](https://github.com/Lanpropro/DD_Monitor_Plugins/pull/67)中保留此待实现边界；本条仅记录调查，不将Issue标为完成或发布新版本。技术依据：[Streamlink YouTube源码](https://github.com/streamlink/streamlink/blob/8.6.1/src/streamlink/plugins/youtube.py)、[yt-dlp PO Token说明](https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide)。
