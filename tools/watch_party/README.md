# 好友同看连接试验

两部设备用浏览器打开同一入口。房主点击「创建房间」，朋友输入六位房间码并点击「加入」。两人点击「准备演示」后，页面按同一个约定时刻显示计时。刷新其中一个页面会用当前标签页保存的临时凭证回到原座位。双方需要重新准备。双方都断开后，服务在约两分钟后回收房间。

本原型用于验证房间连接、状态隔离和重连。演示页使用相同的固定测试标记。服务仅在两人在线且标记相符时约定两秒后的起点。每个浏览器通过往返计时估计与服务器单调时钟的偏差。网络上下行延迟差会影响估计。

朋友换浏览器或聊天内置页面时，请关闭原页面，再输入原房间码。只要房主在线且客席已离线，新页面就能加入。若提示两人都在房间中，请等原连接断开，再点「加入」。

## 本地运行

在插件源码仓库根目录，使用装有 `aiohttp` 的 Python 3.10 或更新版本运行：

```powershell
python tools/watch_party/server.py --port 18764
```

本机打开 `http://127.0.0.1:18764/`。如需外网试验，开发方另开终端，将 Quick Tunnel 指向这个专用端口：

```powershell
cloudflared tunnel --protocol http2 --url http://127.0.0.1:18764
```

两部设备使用隧道给出的同一个 HTTPS 入口，房间码在该入口内有效。好友只需浏览器。房间服务与隧道均需持续运行，结束试验时关闭两个进程。Quick Tunnel 重建后需要重新分享入口。

## 验证

以下检查会通过两个独立客户端进程建房、加入、提交相同或不同的标记、断线重入并重新约时，也会检查其他房间不会收到本房间的状态。可把本地入口换成实际隧道的 HTTPS 入口再运行一次。

```powershell
python tests/check_watch_party.py http://127.0.0.1:18764
```

## 插件同看房间（最多三人）

同一个服务支持插件的 `/live` 连接，网页和插件的房间分别管理。此独立服务支持上一版的集中式测试。新版在插件中复用同一 Python 匹配服务，建房方式、查号服务部署与测试见 ../watch_cloud/README.md。房主和朋友都从插件建房或加入。服务端可使用 `--observations 文件路径` 保存房间号、服务器单调时钟、测得的画面时差、往返延迟和计划校准时刻，供本机复核。隧道重建后需要更新测试包入口。

两到三台设备各自播放同一主播并设为主画面。在右下角弹幕控制台切换到「好友同看」，房主创建，朋友输码加入。全员使用相同的对照区域，初测可使用默认全幅画面。切回弹幕页或收起控制台后同看继续，任意一端均可手动要求全员立即复核。主画面最小化、隐藏或在后台停止绘制时，使用本地播放时钟和当前主路偏移寻找对应帧指纹。包含这种样本的复核会标为时钟估计。

至少两人在线时，主路播放倍率取 1.0×，原有耗尽等待及恢复缓冲继续生效。首次匹配进入容差后，丢弃已用指纹，再用另一段新画面复核。两次均在原有容差内且相差不超过 140 毫秒，全员才显示「已锁定」。锁定后客户端停止取样及发送指纹，服务端停止画面比较。锁定时各端仅本地观察主路媒体进度与经过时间，另保留连接及诊断。仅缓存余量变化不发起复核；播放等待、主路解码历史更换或进度偏离正常速度累计达 200 毫秒，等本机有可播放画面且按正常速度连续前进约 1 秒后重新复核。成员加入、退出或重连后，全员重新取样。卡片只列在线成员，公开平台和 ID 取自各自客户端侧栏，未登录显示访客。切换账号仅更新房内展示，诊断日志不保存这些字段。服务先测出各成员相对同一参考端的时差。只有三次测量中各成员间的相对偏差变化均不超过 140 毫秒，且某端每次领先最慢者都超过 350 毫秒与全员往返延迟均值加 70 毫秒中的较大值，才安排该端延后。同时需要延后的成员共用同一约定时刻。手动复核立即重新收集全员证据，沿用同一回调规则。

服务端记录房主与朋友各自约两秒的主路视频包数、解码帧数、提交和绘制或 Present 数、界面定时器最大间隔、缓存余量与校准执行回执。解码最大间隔取最近一秒，D3D11 提交间隔取工作线程已记录的长间隔。后台时钟估计和物理显示时差需要分开解读。

倍率诊断以百万分数存储，1000000 代表 1.0×。`rate_ppm` 是主路使用的倍率，`device_rate_ppm` 是最近一次音频设备播放位置所在输出块的实际媒体帧倍率，`progress_rate_ppm` 是本端相邻诊断间隔内主路媒体时间增量除以实际经过时间，包含可能的停顿或跳转。缺少设备或时间观察时对应值为 null。
